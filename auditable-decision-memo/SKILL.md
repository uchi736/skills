# 見落としを防ぐ判断メモを作る

判断を伴うリクエストに対して、結論だけを早く出させるのではなく、
「誰に影響するか」「何がまだ分からないか」を外に出させてから結論へ進ませる。
目的はAIに正解を出させることではなく、人間が見落としを点検できる材料をそろえること。

## このスキルを使うタイミング

- 判断そのものだけでなく「誰に影響するか」「何が不確かか」を取りこぼせない場面
- 立場の弱い人や声の小さい関係者にしわ寄せがいきうる判断（採用・顧客対応・ルール変更など）
- 医療・法務に近い判断や、複数の利害が衝突する判断
- AIエージェントに判断や下書きを任せ、その結論を人間が確認したい場面

単純な事実問い合わせや、影響範囲が自明で当事者が1人だけの軽い判断には使わない。

## なぜこの型が効くのか（前提知識）

「順を追って考えて」とだけ指示すると、複雑な判断でも段階的に考えさせれば
論点は自然に出る、という前提に乗ることになる。だが実際には2つの弱点が出やすい。

- **関係者の収束**：利害を持つ当事者を1人しか、あるいは誰も挙げないまま判断する
- **不確実性の抑圧**：何が不明かを示さないまま、確信を持って結論へ踏み切る

経験則として、これは特定モデルの癖ではなく、ベンダーやモデル規模をまたいで現れる。
有効な対処は、抽象的な「ステップ」ではなく、登場人物のいる「物語」の形で考えさせること。
物語（人物がいて、出来事が連鎖し、先が読めない状況）は学習データに濃く存在するため、
モデルは因果の道筋を一から組むのではなく、慣れた物語のパターンを使って埋められる。

重要な性質が2つある。

- **文字数ではなく構造が効く**：単に長く詳しく書かせるだけでは、連続的な指標で測ると
  網羅性・不確実性の差は埋まりきらない。順番と「何を明示させるか」が結果を分ける。
- **部品ごとに効く**：5つの区切りはそれぞれ担当する指標を独立に押し上げる。
  ある区切りを外しても他はほとんど影響を受けない。必要な部分だけ既存プロンプトに足せる。

## 全体フレームワーク

```
判断を伴うリクエスト
        │
        ▼
  当事者は1人か / 複数の立場が本当に衝突するか
        │
   ┌────┴───────────┐
   ▼                ▼
 単一の判断者        立場が衝突（一方の利得が他方の損失）
   │                │
   ▼                ▼
 5区切りの判断メモ   3視点の合議（議論→統合→賛否投票）
   │                │
   ▼                ▼
 人間が点検  ◄──── 最後まで残った反対を人間へエスカレーション
```

判断の分岐基準：明確な決定者がいて利害が根本的には衝突しないなら単一の判断メモで足りる。
誰かの要求を通すと別の誰かの取り分が直接削られる構造なら、多視点合議に進む。

## 基本：5区切りの判断メモ（単一の判断者）

結論の前に、次の5つをこの順で書かせる。各区切りは「何を書かせるか」と
「外すと何が崩れるか（＝その区切り固有の効果）」をセットで押さえる。

### 1. 誰が判断するのか
判断する人・組織の立場、役割、いま分かっていること・分かっていないことを書かせる。
抽象的な「意思決定者」ではなく具体的な誰かを置くと、以降の推論がその視点に固定され、
話が宙に浮きにくくなる。経験則：この区切り単体の数値効果は小さいが、後続4つを載せる土台になる。

### 2. 誰に影響するのか（最重要）
判断で暮らしや利害が変わる関係者を、直接の当事者だけでなく、間接的に影響する人・
背景の組織・見落とされがちな第三者まで広げて挙げさせ、各自が何を得て何を失いうるかを書かせる。
経験則：これが「関係者の収束」を直接ふせぐ区切り。外すと関係者の網羅性がはっきり落ち、
一方で因果や不確実性の指標はほぼ動かない（この区切り固有の効果）。

### 3. 選択肢ごとに何が起きるのか
現実的な選択肢を挙げ、それぞれについて結果を最低2手先まで、しかも挙げた関係者ごとに追わせる。
「店がうるおう」で止めず、その次に何が起き、誰にどう跳ね返るかまで展開させる。
経験則：外すと因果の連鎖の深さが下がり、波及を追わせる作業が「結果を受ける相手」を
自然に名指しさせるため、関係者の見落としも副次的に減る。

### 4. 何が分からないのか（最重要）
各選択肢について、判断を左右しうる不明点を具体的に書かせる。「不確実です」と
ぼかすのではなく、前提が崩れる可能性や読み切れない反応を名指しさせ、
解消されたら結論が変わりうる不明点はその旨も書かせる。
経験則：これが「不確実性の抑圧」を直接ふせぐ区切りで、5つの中で単体の変化が最も大きい。

### 5. それでも何を選ぶのか
ここまでの関係者・結果・不明点を踏まえ、現時点で最も妥当な判断を1つ、
他より望ましい理由とともに示させる。別枠の「判定」ではなく物語の締めくくりとして語らせ、
最後に残っている不確実性と、人間が追加で確認すべき点を必ず明示させる。
経験則：結論の区切り自体の数値効果は小さいが、4つを受け止める出口として機能する。

### 判断メモのテンプレート

内部の思考を逐語的に長く吐かせるのではなく、人間が確認できる「判断メモ」を
作らせる形が扱いやすい。次を起点に、対象業務に合わせて調整する。

```
あなたは、利害が衝突しうる判断を支援するAIです。
結論を急がず、以下の順で「判断メモ」を作ってください。
内部で考えたことを逐語的に出すのではなく、人間が確認できる根拠だけを簡潔に書いてください。

1. 誰が判断するのか
   判断する人や組織の立場・役割、いま分かっていること・分かっていないことを書く。

2. 誰に影響するのか
   影響を受ける人・組織・第三者を、直接の当事者だけでなく
   間接的に影響する人や見落とされやすい人まで含めて広く挙げる。
   それぞれが何を得る可能性があり、何を失う可能性があるかを書く。

3. 選択肢ごとに何が起きるのか
   現実的な選択肢を挙げ、それぞれ少なくとも2手先まで結果を追う。
   ある人への影響が別の人や組織にどう波及するかも書く。

4. 何がまだ分からないのか
   各選択肢について、判断を左右しうる不明点を具体的に挙げる（「不確実」で済ませない）。
   解消されれば結論が変わりうる不明点は、その点も書く。

5. それでも何を選ぶのか
   上記を踏まえ、現時点で最も妥当な判断を1つと、その理由を示す。
   最後に、残っている不確実性と、人間が確認すべき点を明示する。
```

見るべきはAIの結論そのものではなく、結論に至る前に関係者・不利益・波及・未確認事項が
外に出ているか。採用・顧客対応・社内ルール変更・医療や法務に近い判断では、
AIの答えをそのまま採用せず、この判断メモを人間が点検する前提で使う。

## 立場が衝突する判断：3つの視点で合議させる

1つのAIにまとめて考えさせると、強い立場や分かりやすい論点に寄りやすい。
誰かの要求を通すと別の誰かの取り分が直接削られる構造の判断では、
最初から立場を分けて検討させる。

役割は3つに分ける。
- **公式に判断する立場**：判断を下す責任を持つ人・組織
- **最も影響を受ける立場**：生活・権利・仕事・負担が最も変わる人・組織
- **第三者の立場**：当事者ではないが公共性・倫理・長期影響・周辺波及を見られる立場

手順は、各立場が5区切りで最初の意見を述べ → 互いに反論し → 反論を踏まえ最終意見を出し →
モデレーターが3者の修正要求を1本の提案に統合し → 各立場が「賛成／反対」で投票する。

経験則：選択肢を固定して議論させるだけでは全員一致はごく一部にとどまり、選択肢を
開いても自発的にはまとまりにくい。3者の修正要求を1本に織り込み、最後に二択で問うと、
全員一致が大きく跳ね上がる。

### 多視点合議のテンプレート

```
あなたは、利害が衝突しうる判断を整理するモデレーターです。
以下の判断について、3つの立場を分けて検討してください。

【判断したいこと】 …

【立場】
A. 公式に判断する立場
B. 最も大きな影響を受ける立場
C. 第三者の立場（公共性・倫理・長期影響・周辺波及）

1. 各立場の最初の意見
   A・B・Cそれぞれ、(判断者) (関係者) (主な選択肢と2手先の結果) (まだ分からないこと)
   (現時点の立場) を短く整理する。
2. 相互反論
   互いに、相手の見落とし・過小評価している不利益・未確認の前提を具体的に指摘する。
3. 各立場の最終意見
   反論を踏まえた最終的な立場を示し、変えた点があれば理由も書く。
4. 統合案
   3者の要求をできるだけ反映した1つの提案を作る。折衷案ではなく、
   誰のどの懸念に対応したのかが分かるようにする。
5. 賛否投票
   A・B・Cが統合案に「賛成」または「反対」で投票する。
   反対なら、どの利害がまだ直接損なわれているかを明示する。
6. 人間に確認すべき論点
   残った反対・事実確認が必要な点・人間が判断すべき価値判断を分けて列挙する。
```

### 残った反対の読み方

見るべきは全員一致そのものではなく、どの反対が最後まで残るか。
経験則として、統合案を出してもなお却下される反対は割合としてはごく一部で、
「一方の要求を通すと別の当事者の利害が直接損なわれる」役割に集中する。
モデレーターが吸収できる反対は手続き上の摩擦として処理できるが、
統合案でも消えない反対は、誰かの取り分が本当に削られている合図。
そこはAIに丸め込ませず、人間に戻すべきエスカレーション論点として扱う。

## プロンプトを自動改良するときの注意

上のテンプレートを自動最適化（現在のプロンプトと採点結果から弱点を診断し書き換える手法）
にかける場合、改良案を採点する「審査役」モデルの選び方が効く。

経験則：複数ベンダーのモデルで使う前提なら、審査役は文章を生成するモデルとは
**別ベンダー**から選ぶ。同じ系統の審査役だと、仕様そのものではなくその系統特有の解釈まで
満たすよう最適化が進み、他ベンダーで通りにくいプロンプトになりやすい。別ベンダーの審査役の
ほうが、効果が大きく・出力が短く・身内びいきも小さくなる傾向がある。追加の学習コストはない。
（この知見はこの種の判断タスクで得られたもので、領域外への一般化は未確認。）

## 制限事項と注意点

- **適用範囲**：検証は日常的な個人・市民の道徳的ジレンマが中心。臨床トリアージ・法務・
  多者間の政策調整のように専門知識が強く問われる領域への転移は未確認。
- **副作用のモデル差**：あるモデルではこの型で慎重さが増し、本来断る必要のない安全な依頼まで
  断る「過剰拒否」が上がった（13.6%→23.6%）。別系統のモデルでは拒否挙動に有意な変化なし。
  導入時はモデルごとに過剰拒否を点検する。
- **効果の出方のモデル差**：一部のモデル系統では、文字数の影響を差し引くと優位がほぼ消える。
  これらは「順を追って考えて」の段階で既に単位文字数あたり同等の密度で関係者・不確実性を
  書いており、上乗せ分は主に文字数の増加による。
- **安全性の保証ではない**：これは判断の自動化ではなく、判断の根拠と対立点を
  監査しやすい形で外に出すための道具。最終判断は人間が担う前提で使う。
- **「なぜ効くか」は仮説含み**：効果の理論的裏づけの一部（推論の跡を圧縮しやすさで測る指標など）
  は再現せず、その点は提唱側でも「主張の反証であって裏づけではない」と明記されている。

## 発展的応用

- 5区切りのうち必要な部品だけを既存プロンプトに足す（関係者の網羅だけ、不確実性の明示だけ等）。
- 監査ログとして判断メモを保存し、後から「誰に影響し・何が不確かだったか」を追跡可能にする。
- 多視点合議の役割を業務に合わせて増減する（例：規制対応では「規制当局視点」を第三者に充てる）。
