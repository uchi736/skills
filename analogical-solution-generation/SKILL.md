# 異分野アナロジーによる解法生成

未解決の問題に対して、LLMに直接「解け」と頼むのではなく、まず遠い分野へのアナロジーを作らせ、そのアナロジーを手がかりにして解法を探させる二段構えのワークフロー。狙いは、似たような解ばかり出てくる状態を抜け出し、多様で新規な候補を量産すること。

## このスキルを使うタイミング

- 一つの問題に対して、できるだけ多様な切り口の解法候補を集めたいとき
- LLMに解法を聞くと毎回同じような定番手法ばかり返ってきて行き詰まったとき
- 既存の探索手法やアイデア生成システムに、新規な候補を補充したいとき
- 研究テーマの方向づけや、実装前のブレインストーミングの土台がほしいとき

逆に、答えがほぼ一つに決まっている問題や、定番手法で十分な問題には向かない。このスキルは「広げる」ためのもので、「正解を一つ当てる」ためのものではない。

## 前提知識：なぜアナロジーを挟むと多様性が出るのか

LLMに開放的な問題（決まった正解のない問題）の解法を尋ねると、最も尤度の高い定番解へ収束する。たとえばタンパク質の立体構造予測なら、ほぼ毎回同じ著名手法に張り付く。これがモード崩壊で、探索すべき空間を実質的に狭めてしまう。

重要な観察が一つある。「他の分野から解を探してきて」と指示しても、収束はあまり防げない。分野を変えろと言うだけでは、LLMはやはり似た発想に落ちる。効くのは、解そのものを探させる前に、明示的にアナロジーを作らせる手順を挟むこと。アナロジーの空間は、解を直接想起する空間よりも広いため、ここを経由させると出力が散る。

アナロジーの作り方には流儀がある。表面的な見た目の似ているものを結びつけるのではなく、関係構造が共有されているかで結ぶ（認知科学の構造写像理論に基づく）。アナロジーは次の二つの部品でできていると考える。

- オブジェクト対応：問題側の要素と、別分野側の要素を一対一で対応づける
- 共有される関係：それらの要素の間に成り立つ関係のうち、両分野で共通して成り立つもの

ここで写すのは関係であって、属性ではない。原子と太陽系のたとえで言えば、写すのは「Aが Bの周りを回る」「Bが Aを引きつける」という関係であり、「電子は小さい」「太陽は熱い」といった属性は写さない。

写像の良し悪しは機能で判断する。「ペイロードを運ぶ」という機能的な対応根拠は良いが、「どちらも液体だ」という見た目の対応根拠は悪い。何であるかではなく、何をするかで対応させる。

もう一つ、写像は完全である必要はない。問題が持つ関係のすべてをアナロジー先が網羅していなくてよい。部分的に重なっていれば、そこから解を引き出せる。

## 全体フレームワーク

```
[問題文] 
   │  Phase 0: 問題文の前処理（解法分野のヒントを除去）
   ▼
[中立化された問題文]
   │  Phase 1: 抽出（1回のLLM呼び出し）
   │    ・問題のオブジェクトと関係を取り出す
   │    ・遠い分野への複数アナロジーを生成
   ▼
[アナロジー群：各々がオブジェクト対応＋共有関係を持つ]
   │  Phase 2: 探索（アナロジー1つにつき1回のLLM呼び出し）
   │    ・各アナロジー先の分野で実在する手法を1つ探す
   │    ・接地された検索で出典・コードの幻覚を防ぐ
   ▼
[解法候補群：各々が出典付き]
   │  Phase 3（任意）: 実装・検証
   ▼
[実装された解法と性能評価]
```

抽出と探索を分けるのが肝心。一気にやらせると、アナロジーを作る思考が省略されて定番解に戻る。

## 各フェーズの詳細

### Phase 0：問題文の前処理

公開論文や既存資料から問題文をそのまま持ってくると、たいてい解法側の分野のヒントが文中に漏れている。「〜の信号を雑音から取り出す」のような書き方をしていると、LLMはその語感に引っ張られて発想が縛られ、かえって収束が強まる。

やること。問題文を「達成したいことだけ」に絞って書き直す。

- 目的だけを述べ、仕組みや手法の語を消す
- 解法分野の専門用語を取り除く
- 「〜によって」「〜を用いて」のような手段を示す句を削る
- 「どうやって〜するか」という形に整える

例として、「自己相関が支配的な神経信号から半球間の結合を分離するにはどうするか」という問題なら、特定の信号処理用語を抜き、「片方の系の影響を、各系の強い自己相関に埋もれさせずに取り出すにはどうするか」のように一般化する。同じ中立化された問題文を、後段のすべての設定に同じ条件で渡す。

### Phase 1：抽出

中立化した問題文を入力に、抽出役のLLMを1回呼ぶ。temperatureは1.0に上げ、発想を散らす。出力させるのは次のもの。

- 問題の要約（1〜2文）
- 問題のオブジェクト（要素）とその機能的な役割
- オブジェクト間の中核的な関係
- 複数のアナロジー（各々に、対象分野名・対応の根拠付きオブジェクト対応・共有関係を含める）
- 重要語のリスト

アナロジーは一度に複数（目安として数件〜十数件）作らせる。多様性は数で稼ぐ。対象分野は、なるべく問題から遠い分野を狙わせる。距離が遠いほど新規な解が出やすい傾向があるためで、これは後述の経験則とつながる。

抽出プロンプトに織り込む構造的要素（逐語的なテンプレートではなく、自分の言葉で組み立てる指針）。

1. 役割設定：問題から異分野の解を機能的対応によって探すための分析役だと宣言する
2. 抽出指示：問題のオブジェクトと関係をまず取り出させる
3. アナロジー生成指示：指定した件数だけ、別分野への対応を作らせる
4. 機能写像の明示：見た目ではなく機能で対応づけよと一文で釘を刺す
5. 出力形式：機械処理しやすいよう構造化（JSON等）し、余計な前置きを禁止する

### Phase 2：探索

抽出で得たアナロジーを一つずつ使って、探索役のLLMを呼ぶ。アナロジー1件につき1呼び出し、temperatureは1.0。各呼び出しには、問題そのものと、そのアナロジー（対応・共有関係）を渡す。

探索役への要点は、問題の分野で直接解を探すのではなく、アナロジー先の分野で、対応表の右側（別分野側の要素）に対して働く実在の手法を探させること。共有関係を保ったまま、その手法を問題側へ引き戻せるかを問う。

出典の正確さがここでの最大の落とし穴。LLMは存在しない論文やリポジトリを自信たっぷりに挙げる。対策として、探索プロンプトに次を入れる。

- 各解法は具体的な一次資料に基づくこと
- 一つの資料を複数の解法に使い回さないこと
- 論文の正式名称を省略・改変せず正確に書くこと
- 公開実装（リポジトリ）があれば添えること、なければ空でよいこと

経験則として、案出だけなら通常のLLMで十分だが、実装まで進める前提で出典とコードの正確さが要るなら、探索役を接地検索（ウェブ・文献検索に強いツール）に差し替えると幻覚が大きく減る。案出フェーズと、実装に向けた裏取りフェーズで道具を使い分けるとよい。

探索プロンプトに織り込む構造的要素。

1. 役割設定：指定分野から問題に転用できる手法を探す役だと宣言する
2. 文脈提供：中立化問題、アナロジー題、オブジェクト対応、共有関係、重要語を渡す
3. 探索範囲の限定：別分野側の要素に対して働く手法を探し、問題分野の直接解は探さないと指示する
4. 出典規律：上記の正確さ要件を明記する
5. 出力形式：各解法に題・出自分野・短い説明・中核技術・転用根拠・出典・実装リンクを持たせ、構造化して返させる

### Phase 3（任意）：実装と検証

有望な解法を選び、実際に動かして既存手法と比べる。論文の事例では、解法の説明・出典・コードをコーディングエージェントに渡し、人手の介入を最小にして実装している。多くの場合、転用された手法はそのままでは問題に合わないので、土台のアイデアを保ちつつ問題側に合わせて調整する前提で臨む。

検証では、既存の強いベースラインと、ベースライン＋新手法のハイブリッドの両方を測ると示唆が得られやすい。新手法単独が一部の指標で劣っても、ベースラインと組み合わせると大きく改善する場合がある。

## 判断基準と経験則

良いアナロジーの三つの軸。後段の評価でも使えるし、生成時に自分でチェックする基準にもなる。

- 構造的深さ：オブジェクト対応がどれだけ意味のある、説明力のある対応になっているか
- ドメイン距離：問題分野と別分野がどれだけ離れているか。遠いほど良い
- 新規性：その対応がどれだけ独創的で非自明か

ドメイン距離は強い指標になる。距離の遠い順に解の新規性が上がる傾向があり、おおむね「制約なし探索 < 単なる別分野探索 < このアナロジー手法」の並びになる。アナロジー手法は、人手で用意した模範アナロジーよりも新規性で上回ることさえある。なお構造的深さは人でも判定が割れやすく、当てにしすぎないほうがよい。

トレードオフを正直に扱う。新規性の高い解は、「妥当な解に見える」割合がやや下がる。突飛さと妥当さは引き換えになりやすい。だからこの手法は、既存の探索やアイデア生成を置き換えるものではなく、探索空間を広げる多様性の供給源として組み込むのが正しい使い方。出てきた候補は当たり外れがある前提で、複数を篩にかける。

数で稼ぐ。一つの問題に対してアナロジーも解も複数生成し、多様性を確保してから絞る。安価に回せる手法なので（一問あたり数セント規模）、惜しまず本数を出す。

機能で写すという原則は、生成時にも検証時にも効く。対応の根拠が「同じ働きをする」になっているかを毎回見る。「同じ見た目」「同じ材質」になっていたら、その対応は弱い。

- [ ] 出てきた候補を「当たり外れあり」として複数で評価したか

## 制限事項と注意点

すべてのアナロジーが使える解に化けるわけではない。発想は大きく広がるが、その実現可能性を見極める工程がボトルネックとして残る。生成された候補は仮説であって、検証を経ていない。

このワークフローは解の生成段階だけを切り出している。データ取得から実装・評価までを通した一気通貫の自動パイプラインに組み込むには、別途つなぎ込みが要る。

検証された事例は生命科学系の問題に偏っている。枠組み自体は分野を選ばないが、他分野での効き目は自分の領域で確かめながら使う。

安全面。多様な解を生む力は、悪用すれば有害な手順の案出にも向きうる。生成された候補をそのまま実行可能な指示として扱わず、特に危険を伴う領域では実装前に十分な確認を挟む。

## 発展的応用

- 既存のアイデア生成システムや探索手法の前段に置き、新規候補を注入する多様性エンジンとして使う
- 抽出で得たアナロジー群そのものを、研究の切り口リストとして人が眺める
- 実装・評価エージェントと連結し、生成から検証までを半自動で回す
- 分野間の対応表（どの問題分野が、どの別分野の手法と相性が良いか）を蓄積し、次の問題の当たりをつける材料にする
