# BDIオントロジー設計スキル: エージェントの心的状態をモデリングする

エージェントの信念（Belief）・欲求（Desire）・意図（Intention）を
構造化された知識表現としてモデリングし、記号的推論と
ニューロシンボリックシステムを統合するための設計パターン。

## このスキルを使うタイミング

- マルチエージェントシステムでエージェントの心的状態を明示的にモデリングしたい
- LLMの出力に論理的一貫性を持たせるために記号的バックボーンが必要
- エージェントの意思決定プロセスを説明可能（Explainable）にしたい
- RDFトリプルとエージェント内部の推論プロセスを双方向に接続したい
- 認知アーキテクチャに基づくオントロジー設計パターン（ODP）を構築したい

---

## 前提知識

BDIモデルは哲学者Bratmanが1980年代に提唱した実践的推論の理論に基づく。
核心的な洞察は以下の3点：

1. **信念（Belief）** = 情報的側面。エージェントが世界について真だと考えていること
2. **欲求（Desire）** = 動機的側面。エージェントが実現を望んでいること。行動へのコミットメントは含まない
3. **意図（Intention）** = 熟慮的側面。特定の目標達成に対するエージェントのコミットメント。欲求と行動を橋渡しする

**設計上の重要な判断ポイント:**

- 目標（Goal）は欲求の特殊形態として扱わない。認知層（信念・欲求・意図）と行動計画層（目標・計画）を明確に分離する。これにより、目標を複数エージェント間で共有・合意・伝達できるようになる
- 意図間の衝突は、オントロジーの公理ではなく推論層（またはLAG層）で検出させる。これにより中核語彙の柔軟性を保てる
- 心的状態は静的な構造ではなく、生成・修正・抑制される動的なプロセスとしてモデリングする

## 全体フレームワーク

BDIオントロジーは4つのモジュールで構成される：

```
┌─────────────────────────────────────────────────────────┐
│ Module 1: 世界・エージェント・心的エンティティ            │
│   WorldState ← perceives ← Agent → cognises → MentalEntity │
│                                                         │
│ Module 2: 心的状態の動態                                 │
│   Belief → motivates → Desire ← fulfils ← Intention    │
│   MentalProcess → affects (generates/modifies/suppresses)│
│                                                         │
│ Module 3: 目標と計画                                     │
│   Intention → specifies → Plan → addresses → Goal       │
│   Planning (MentalProcess) → defines → Plan             │
│   Plan → hasComponent → Task (ordered sequence)          │
│   PlanExecution → satisfies → Plan, bringsAbout → WorldState│
│                                                         │
│ Module 4: 時間推論                                       │
│   MentalEntity → atTime → TemporalEntity                │
│   MentalEntity → hasValidity → TemporalEntity           │
│   TimeInterval = hasStartTime + hasEndTime              │
└─────────────────────────────────────────────────────────┘
```

再利用する既存のオントロジー設計パターン（ODP）:
- **EventCore**: 時間中に発生し参加者を伴うイベントのモデリング
- **Situation**: 特定時刻に成立するエンティティ構成の表現
- **Provenance**: 心的状態の因果的・推論的基盤の表現
- **BasicPlan**: 目標実現、行動仕様、充足条件の表現
- **TimeIndexedSituation**: 時間に紐づいた状況の表現
- **Sequence**: タスクの順序付き系列の表現

基盤オントロジーとしてDOLCE+DnS UltraLite (DUL) に整合させる。

## 各モジュールの詳細

### Module 1: 世界・エージェント・心的エンティティ

**目的:** エージェントと外部世界、そしてエージェントの内部認知状態の関係を定義する。

**モデリングすべきクラスと関係:**

| クラス | 上位クラス | 役割 |
|--------|-----------|------|
| WorldState | d0:Eventuality | 環境の状態。エージェントの視点とは独立 |
| Agent | dul:Agent | 知覚・推論・行動が可能な自律的エンティティ |
| MentalEntity | d0:CognitiveEntity | 心的オブジェクトまたはコンテンツ |
| MentalState | MentalEntity | 信念・欲求・意図の上位クラス |

**主要な関係:**
- `Agent → perceives → WorldState`（エージェントは世界状態を知覚する）
- `Agent → cognises → MentalEntity`（エージェントは心的エンティティを認知する）
- `MentalEntity → refersTo → WorldState`（心的エンティティは世界状態を参照する）
- `MentalEntity → hasPart → MentalEntity`（心的エンティティは部分構造を持てる）

**設計のポイント:**
- WorldStateはエージェントの視点とは独立した「参照基盤」として機能する。心的状態はこのWorldStateに向けられる（志向性）
- `hasPart`により心的エンティティを分解可能にする。例：「会議が10時にRoom 5で始まる」という信念を、時間成分と場所成分に分解できる。これにより、部分的な信念更新が可能になる

### Module 2: 心的状態の動態

**目的:** 信念・欲求・意図がどのように生成・変化・相互作用するかをモデリングする。

**心的状態間の因果関係（3つの核心的関係）:**

```
Belief ──motivates──→ Desire
Belief ──supports───→ Intention
Intention ──fulfils──→ Desire
```

- 信念が欲求を動機づける（例：「店が開いている」→「食料品を買いたい」）
- 信念が意図を支える（例：「店が開いている」→「食料品を買いに行く」）
- 意図が欲求を充足する（例：「買いに行く」が「買いたい」を実現する）

**心的プロセス（MentalProcess）:**

心的プロセスは `MentalEntity` と `d0:Activity` の両方のサブクラスとして設計する（二重性質）。

| プロセス種別 | 影響対象 | 例 |
|-------------|---------|-----|
| BeliefProcess | Belief | 新しい情報を受けて信念を形成・更新する |
| DesireProcess | Desire | 内的動機や環境変化に基づき欲求を生成・修正する |
| IntentionProcess | Intention | 欲求の優先順位付けと行動可能なコミットメントの選択 |

**心的プロセスが心的状態に影響を与える3つの方法:**
1. **generates（生成）**: 新しい心的状態を生み出す
2. **modifies（修正）**: 既存の心的状態を変更する
3. **suppresses（抑制）**: 心的状態を無効化する

これら3つは `affects` プロパティのサブプロパティとして定義する。

**心的プロセスの構造:**
- `reasonsUpon → MentalState`（既存の心的状態に基づいて推論する）
- `isTriggeredBy → MentalEntity`（心的エンティティにトリガーされる）
- `isProcessedBy → Agent`（エージェントが処理する）

**正当化（Justification）:**
- `dul:Description`のサブクラスとして定義する
- `justifies → MentalEntity`で心的エンティティの根拠を明示する
- 説明可能性の核心。エージェントがなぜその心的状態を保持しているかを追跡できる

### Module 3: 目標と計画

**目的:** 意図から計画・目標への接続、および計画の実行をモデリングする。

**なぜ目標を欲求のサブクラスにしないのか:**
- 目標を `dul:Goal`（記述）として扱い、`MentalState` の外に置く
- 認知層と行動計画層の分離を維持する
- 複数エージェントが同じ目標記述を共有できる
- 目標には宣言的側面（達成したい状態の記述）と手続き的側面（達成のための計画群）がある

**計画の構造:**
```
Intention → specifies → Plan → addresses → Goal
                          ↓
               hasComponent → Task (ordered)
               beginsWith → Task
               endsWith → Task
               Task → follows → Task (transitive)
```

**計画実行（PlanExecution）:**
- `satisfies → Plan`（どの計画を実行しているか）
- `addresses → Goal`（どの目標に対応するか）
- `hasComponent → Action`（具体的なアクション群）
- `bringsAbout → WorldState`（結果として生じる世界状態）
- `isExecutedBy → Agent`
- `atTime → TemporalEntity`

**TaskとActionの区別:**
- **Task**: 計画内の抽象的・記述的な行動仕様
- **Action**: 環境内で実際に実行された具体的活動
- `Action → isExecutionOf → Task` で両者を接続する

### Module 4: 時間推論

**目的:** 心的状態とプロセスの時間的側面を明示的にモデリングする。

**時間構造:**
- `TemporalEntity`（dul:Regionのサブクラス）
  - `TimeInstant`: ゼロ期間の時間点
  - `TimeInterval`: 開始と（オプションで）終了を持つ時間区間
    - 正確に1つの `hasStartTime → TimeInstant`
    - 最大1つの `hasEndTime → TimeInstant`（開区間を許容）

**心的エンティティの時間的配置（2つの補完的な視点）:**
- `atTime → TemporalEntity`: 時間的アンカリング（いつ発生したか）
- `hasValidity → TemporalEntity`: 時間的有効性（いつまで有効か）

この二重構造により、「信念がいつ形成されたか」と「信念がいつまで保持されているか」を区別して問い合わせできる。

## 実装ガイド

### OWL 2での実装

- 表現力: SROIQ(D)（ロール階層、逆プロパティ、限定数量制限、データ型をサポート）
- 基盤オントロジーとの整合はメインオントロジーとは別ファイルで管理する（モジュラー戦略）
- これにより、DULなしでも、DULと組み合わせても利用できる

### コンピテンシー質問（CQ）による要件定義と検証

オントロジー設計は以下の4カテゴリ18問のCQによって駆動する。
設計後、各CQに対応するSPARQLクエリで検証する。

**カテゴリ1: 世界・エージェント・心的エンティティ（CQ1-5）**
- 心的エンティティとは何か？
- エージェントはどの心的状態を保持しているか？
- ある心的エンティティの構成要素は何か？
- エージェントはどの心的プロセスを経たか？
- ある心的状態が参照する世界状態は何か？

**カテゴリ2: 心的状態の動態（CQ6-11）**
- どの信念がある欲求の形成を動機づけたか？
- ある意図はどの欲求を充足するか？
- どの心的プロセスが特定の信念・欲求・意図を生成したか？
- 心的エンティティはいつ生成されたか？
- 何が心的プロセスをトリガーしたか？
- どの正当化が特定の心的エンティティを支持しているか？

**カテゴリ3: 目標と計画（CQ12-15）**
- ある意図または計画はどの目標を達成しようとしているか？
- ある意図はどの計画を指定しているか？
- どの計画策定プロセスが特定の計画を作成したか？
- ある計画を構成するタスクの順序付き系列は何か？

**カテゴリ4: 時間推論（CQ16-18）**
- ある心的状態の時間的有効性（開始・終了時刻）は何か？
- 特定の時点で有効だった心的状態は何か？
- ある心的エンティティは時間経過でどう変化したか？

### LLMとの統合（Logic Augmented Generation）

BDIオントロジーをLLMのプロンプトに含めることで、以下の能力を強化できる：

**推論能力の強化:**
- 論理的矛盾の検出精度が向上する（経験則として、プレーンなLLM単体では見落とす矛盾の一部をオントロジー付与で検出可能になる）
- 特に、行動の前提条件と信念の整合性チェックに有効

**モデリング能力の強化:**
- LLMがBDIオントロジーに準拠したRDFトリプルを正しく生成できる
- 心的プロセスの因果チェーン（知覚→信念形成→欲求→意図→計画）を一貫して追跡可能

**LAGの実践手順:**
1. BDIオントロジー（TTL/OWLシリアライゼーション）をシステムプロンプトに含める
2. タスク記述と環境コンテキストをユーザープロンプトとして与える
3. LLMにBDI準拠のRDFトリプル生成を求める
4. 生成されたトリプルが以下を含むか検証する：
   - エージェントの信念とその参照する世界状態
   - 信念→欲求→意図の因果チェーン
   - 正当化（Justification）による説明可能性
   - 計画と目標への接続
   - 時間的アンカリング

### BDIフレームワークとの統合（T2B2Tパラダイム）

RDFトリプルとエージェントの心的状態を双方向に変換する：

```
RDFトリプル（ドメイン知識）
    ↓  Triples-to-Beliefs
エージェント内部の信念ベース
    ↓  BDI推論（Prolog風ルール）
推論結果
    ↓  Beliefs-to-Triples
RDFトリプル（知識グラフへ反映）
```

Prolog風ルールとの対応:
- `[HEAD]`（トリガー信念）= BDIオントロジーのBelief
- `[CONDITIONALS]`（文脈制約）= 補助的な信念群
- `[TAIL]`（実行アクション）= 欲求・意図を実現する計画

## チェックリスト

### 必須事項
- [ ] WorldState、Agent、MentalEntity、MentalState、Belief、Desire、Intentionのクラスが定義されているか
- [ ] Belief→motivates→Desire、Intention→fulfils→Desireの関係が実装されているか
- [ ] MentalProcessによるaffects（generates/modifies/suppresses）が定義されているか
- [ ] GoalがMentalStateのサブクラスではなく、dul:Goalとして分離されているか
- [ ] 時間的配置（atTimeとhasValidity）が心的エンティティに関連付けられているか
- [ ] Justificationクラスにより心的状態の根拠が追跡可能か
- [ ] 各CQに対応するSPARQLクエリで検証を行ったか

### 推奨事項
- [ ] DULとの整合ファイルをメインオントロジーとは分離しているか
- [ ] OPLaXでCQとSPARQLクエリのアノテーションを付けているか
- [ ] OWLUnitでユニットテストを実施しているか
- [ ] w3idなどの永続URIを使用しているか
- [ ] CC-BY-4.0などのライセンスを明示しているか

## 制限事項と注意点

- **意図間の衝突は明示的にモデリングされていない。** 矛盾する意図の検出は推論層（SPARQL、Prolog、LAG）に委ねられる。将来的にはオントロジー自体に衝突モデリングを追加する方向性がある
- **スケーラビリティの検証が限定的。** 大規模マルチエージェントシステムでの性能は未検証。推論サービスとツールサポートの開発が今後の課題
- **LAGの効果はLLMの能力に依存する。** オントロジーを含めることで一部の矛盾検出が改善されるが、すべてのケースで改善されるわけではない。全テストの約4分の1で差が観察された
- **適用ドメインの検証が限定的。** 現時点での実験はタスク管理（MS-LaTTEデータセット）に限定。政策支援、ロボティクス、人間-AI協調などへの汎化可能性は今後の検証課題

## 発展的応用

- **意図-意図衝突のモデリング:** 相互排他的な信念や目標に基づく矛盾する意図の検出・解消メカニズムの追加
- **ドメイン特化の拡張:** BDIオントロジーをODPとして再利用し、政策支援エージェント、災害対応エージェント、ヘルスケアエージェントなどのドメイン固有の形態に特殊化する
- **マルチエージェント間の目標共有:** 目標をMentalStateの外に配置した設計を活用し、エージェント間で目標記述を共有・交渉するプロトコルの構築
- **LLMエージェントの認知的基盤:** BDIオントロジーをLLMエージェントの「認知的足場」として利用し、推論の透明性と一貫性を担保する
