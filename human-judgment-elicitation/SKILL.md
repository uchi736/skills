# Human Judgment Elicitation: LLMから人間の判断分布を引き出す

LLMに「人々がどう判断するか」を予測させるとき、得られる答えの質はモデルの能力だけでなく
**質問の仕方**で大きく変わる。よく知られた2つの弱点 ——「回答の幅を捉えられない」
「言い換えに弱い」—— の多くは、モデル固有の限界ではなくプロンプト設計の限界である。
このスキルは、人間判断をより正確に引き出すための問い方を、3つの設計課題に整理する。

---

## このスキルを使うタイミング

- LLMに「ある集団の人々がどう答えるか」を予測させたい（世論・意見分布・道徳評価・アンケート回答）
- 単一の代表回答ではなく、**意見の分かれ方・ばらつき**そのものを再現したい
- 調査項目やシナリオが人間にとって明確かどうかを、人間データ収集の前にチェックしたい
- 論争的・道徳的な質問に対して、LLMが単一の「正解」を断定的に返すのを避けたい
- LLMの自己申告する自信（confidence）をどこまで信用してよいか判断したい

---

## 前提知識：核心的な発想の転換

ミスアラインメントには2つの原因がある。(1) モデルの限界、(2) **プロンプトの限界**
（＝聞いていることと、引き出したい人間判断とのズレ）。両者は混同されやすい。

最大の転換点は、**モデルを「1人のノイズの多い回答者」ではなく「人間集団の統計量を
推定する推定器」として扱う**こと。人々の回答の散らばりが欲しいなら、散らばりを
直接尋ねればよい。LLMが返す回答は同じ問いを繰り返しても似通いやすく、その「狭さ」は
モデルが多様性を失っているからとは限らず、**狭くなるような聞き方をしている**結果でもある。

この発想に立つと、3つの課題それぞれに対して「より良い問い」が設計できる。

---

## 全体フレームワーク：3つの設計課題

```
人間判断をLLMで再現したい
│
├─ 課題1: 回答の「分布」を捉えたい（範囲の問題）
│     → 繰り返しサンプリングをやめ、分布を直接尋ねる
│
├─ 課題2: 言い換え・表現変化への頑健性
│     → 「意味を変える言い換え」と「不明確な刺激」を区別する
│     → 刺激の明確さをLLM自身に予測させて事前スクリーニングする
│
└─ 課題3: 信頼度スコアの扱い
      → 人間の不一致の予測には使える / モデル自身の誤差の予測には使えない
```

---

## 課題1: 回答分布を引き出す（最重要）

### アンチパターン：繰り返しサンプリング

最も普及しているが**最も弱い**方法。同じ問いを高温度（temperature=1.0）で数百回投げ、
出力の集まりを人間の分布とみなす。これは検証実験で一貫して最下位だった。

- 高温度でも出力が似通うため、得られる分布は人間の分布よりはるかに狭くなる
- 「LLMは意見の多様性を平均値に潰してしまう」という従来の結論の多くは、この方法に依存している
- ベースライン比較の基準としては有用だが、本番の推定器としては使わない

経験則（分布フィットの目安、距離指標は小さいほど良い）：

| 方法 | TVD目安 | JSD目安 | 評価 |
|------|---------|---------|------|
| 繰り返しサンプリング | ≈ 0.6 | ≈ 0.5 | 弱い（基準線） |
| 良好な分布プロンプト | ≈ 0.3 | ≈ 0.3 | 繰り返しサンプリングの約半分の誤差 |

### 解決策：分布を直接尋ねる5つの手法

| 手法 | 何を尋ねるか | 後処理 | 向いているモデル |
|------|------------|--------|----------------|
| **Proportions（比率）** | 各回答値が選ばれる確率を直接 | JSONをそのまま分布に | 新しい/大きいモデル |
| **Moments: Mean + SD** | 人間回答の平均と標準偏差 | 切断正規分布を構成しビンに離散化 | 小さい/古いモデル、汎用的に頑健 |
| **Moments: Expanded** | 平均・SD・歪度・尖度・二峰性 | モーメントから分布を再構成 | 構造化確率が苦手なモデルの代替 |
| **Hybrid（比率＋モーメント）** | Proportions と Mean+SD の両方 | 2つの分布を平均 | **迷ったらこれ（最も安定して良好）** |
| **SD-only** | 標準偏差のみ | ばらつきの推定だけが欲しいとき | 長いプロンプトより精度が出ることがある |

### モデル別の手法選択ツリー

```
対象モデルは？
│
├─ 新しい/大きいモデル（フロンティア級）
│     → まず Proportions を試す（直接ビン確率が得意）
│     → さらに Hybrid も併用すると堅い
│
├─ 小さい/古いモデル
│     → Moments: Mean + SD を第一候補に
│       （構造化された確率出力でパース失敗・低カバレッジを起こしやすいため）
│
├─ モデル特性が不明 / 1つに絞りたい
│     → Hybrid を既定値にする（平均的に最良、かつ片方が欠けても動く）
│
└─ Proportions がパース失敗・カバレッジ低下する
      → Mean + SD または SD-only に切り替える
```

**重要な経験則：**
- 最良手法はモデルに依存する。「常にこれが一番」という単一の正解はない
- Proportions は当たれば最良級だが、**カバレッジ（有効回答率）が最も低い**。
  弱いモデルでは確率の合計や形式が崩れて使えないことがある
- Mean + SD は構造化出力が苦手なモデルでも安定して機能する、最も堅牢な選択肢
- Hybrid は Proportions と Mean+SD の利点を平均化でき、片方が欠損しても残る方で動く。
  **どれか1つに絞るなら Hybrid を既定値にする**
- 「SDだけを単独で尋ねる」方が、長い複合プロンプトの中で尋ねるより良い推定になることがある

### パラメータと実装上の決まりごと

- **分布プロンプト（Proportions / Moments 系）**: temperature = 0、**1回実行（one-shot）**。
  点推定を安定させるのが目的なので繰り返さない
- **繰り返しサンプリング（基準線比較用のみ）**: temperature = 1.0、数百回（例：500回）反復
- **出力検証 + 1回リトライ**: 返り値がパース可能・スケール範囲内・確率が非負で合計1、を満たすか検証。
  失敗したら同条件でもう1回だけ再実行し、最も完全な有効回答を採用。それでも駄目なら欠損扱い
- **Mean + SD の分布構成**: 平均とSDからスケール境界で切断した正規分布を作り、有効なビンに丸める
- **評価指標**: TVD（全変動距離）、EMD（Earth Mover's Distance）、JSD（Jensen-Shannon距離）の
  3つを併用。いずれも小さいほど良い。指標によって優劣が入れ替わることがあるため1つに頼らない
- **平滑化は表示専用**: 可視化のために曲線を滑らかにしても、距離指標は必ず生の離散分布で計算する

### ペルソナ・プロンプティングについて（個人予測には使わない）

人口統計プロファイルを与えて「この属性の人になりきって答えよ」と指示する方法。
分布レベルでは繰り返しサンプリングより良いが、**直接分布を尋ねる方法には劣る**。
個人レベルの予測精度は低く（弱い相関にとどまり、系統的に偏る傾向がある）、
集団内のばらつきも潰れがち。

- 集団の意見分布が欲しいなら、ペルソナより直接的な分布プロンプトを使う
- ペルソナの結果を「個々人の回答の正確な予測」として解釈しない

## 課題2: 言い換え耐性と刺激の明確さ

### 2種類の「変化」を区別する

言い換えへの不安定さを論じる前に、刺激の変化を2種類に分ける。

| 変化の種類 | 人間はどうなるか | モデルに期待すること |
|-----------|----------------|--------------------|
| **意味を変える言い換え**（害・利益・意図・脆弱性などの道徳的要因を変える） | 人間も判断を変える | モデルも人間と同じ方向に判断を変えるべき |
| **不明確・支離滅裂な刺激**（解釈不能な文、意味の通らない設定） | 人間の判断自体が不安定になる | そもそも安定した正解が存在しない |

この区別を怠ると、「刺激の質の問題」を「モデルの脆さ」と取り違える。

### 経験則

- シナリオが**一貫して解釈可能**に書き直されていれば、たとえ道徳的な意味が変わっても、
  モデルは人間の判断に高い精度で追従する（言い換え版でも元版に近い整合性を保つ）
- 過去研究が報告した「言い換えでモデルが崩れる」現象の多くは、書き換えられた刺激が
  人間にとっても**異常に分かりにくかった**ことに起因しうる。人間の混乱度が高い項目では
  人間回答のばらつきも大きく、それがモデル誤差を押し上げる
- したがって、モデルのロバストネスを評価するときは
  **「一貫した書き換えでの失敗」と「不明確な書き換えでの失敗」を必ず切り分ける**

### LLMによる項目パイロット（混乱度の事前予測）

LLMは「人間が混乱しやすい項目」を予測できる。**新しいモデルほどこの予測精度が高い**
（最新モデルでは人間の混乱度評価と非常に強く相関する）。

応用：人間データ収集の**前に**、LLMに各項目の分かりにくさを採点させ、
低品質・不明確な刺激をスクリーニングする。人間によるパイロットテストと併用すると有効。

混乱度・ばらつきを尋ねるプロンプトの構成要素（逐語コピーではなく構造として）：

```
[シナリオ/項目を提示]
次を順に答えよ（JSONのみ、説明不要）:
  - この項目への自分の評価値（本来のスケール）
  - この文言が人間にとってどれだけ分かりにくいか（1=明快 〜 7=非常に紛らわしい）
  - 人間の回答がどれだけばらつくと予想するか（1=ほぼ一致 〜 7=大きく割れる）
  - 人間回答の標準偏差の推定値（本来のスケール）
  - 上記の自己評価への自分の自信（1 〜 7）
```

### 適用範囲の注意

このアプローチが言うのは「**意味の通る書き換え**には思ったより頑健」ということだけ。
書式の摂動・記号の変化・敵対的な揺さぶりへの頑健性は別問題で、ここでは保証されない。

## 課題3: 信頼度スコアの扱い

LLMの自己申告する自信（confidence）には、**使える用途と使えない用途がある**。

### ✅ 使える：人間側の不確実性の検出

- 人間が混乱したり意見が割れたりする項目で、モデルの自信は**下がる**傾向がある
  （自信と人間回答のばらつきは負の相関）
- 「人間の回答はどれくらいばらつくか」「人間回答のSDはいくつか」を**明示的に尋ねる**と、
  その推定は実際の人間のばらつきとそれなりに相関する
- → 論争的・意見が割れやすい項目を検出する用途には使える

### ❌ 使えない：モデル自身の誤差の予測

- 自信とモデル自身の予測誤差の関係は**モデル依存で不安定**。
  あるモデルでは自信が高いほど正確、別のモデルでは逆、また別では無相関、と一貫しない
- プールすると、自信はモデルの絶対誤差を有意に予測しない
- → モデルの自信を「自分の答えが当たっている確率」の較正済み推定として扱ってはいけない

### 教訓

LLMは**自分の判断の正しさを較正する**より、**人間側の不確実性を感知する**方が得意。
信頼度スコアは「人間がどれだけ割れるか」のセンサーとして使い、
「モデルがどれだけ間違っているか」の保証としては使わない。

- [ ] 分布プロンプトは temperature=0 で one-shot 実行しているか

- [ ] Proportions のカバレッジ低下時に Mean+SD/SD-only へ切り替える経路があるか

- [ ] 「意味を変える言い換え」と「不明確な刺激」を区別しているか

- [ ] 人間データ収集前に、LLMで項目の混乱度をスクリーニングしたか

- [ ] 信頼度を「人間の不一致のシグナル」として使っているか
- [ ] 信頼度を「モデル自身の正しさの保証」として誤用していないか

## 制限事項と注意点

- **検証範囲の限界**: 構造化された数値判断（道徳評価・調査回答）で確認された知見。
  自由記述・説明・助言・複雑な推論など、開放的な出力に一般化するかは未検証
- **分布 ≠ 個人**: 分布プロンプトは集団のばらつきの推定を改善するが、
  個々人の回答の正確な予測ではない（ペルソナ法でも個人予測は弱い）
- **完全には消えない誤差**: 手法を改善してもフィット誤差は残る。性能はモデル・対象集団・
  回答形式によってばらつく。モデルの人間ばらつき推定も中程度の相関にとどまることがある
- **文化・言語による偏り**: 国・文化によって整合性が不均一になりうる。
  特定の国・言語で精度が落ちることを想定しておく
- **良い問いの裏返し**: 「良いプロンプトで上手くいく」ことは、
  「普通のプロンプトで失敗してもよい」ことを意味しない。
  一般的なプロンプトでの失敗自体が重要な限界である。本スキルは
  「プロンプト依存の失敗」と「より深い限界」を切り分けるための道具

## 発展的応用

### システムプロンプト・UI設計への応用
- LLMが平均だけでなく**回答の分布**を推定できるなら、論争的な質問に対して
  単一の権威的回答ではなく**複数の妥当な視点**を提示するよう指示できる
- 意見が大きく割れる問いでは「相当の不一致がある」と明示させ、
  1つの立場が唯一の正解に見えるリスクを下げる
- 混乱しやすいクエリを検出させ、「この回答は不確実」と自ら旗を立てさせる

### 調査・研究ワークフローへの応用
- 人間データ収集の前段に、LLMによる項目パイロット（不明確項目のスクリーニング）を挟む
- 世論・意見分布のシミュレーションでは、繰り返しサンプリングやペルソナではなく
  直接的な分布プロンプト（Proportions / Mean+SD / Hybrid）を標準にする
