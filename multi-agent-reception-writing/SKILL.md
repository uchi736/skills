# マルチエージェント・レセプション駆動型クリエイティブ生成

LLMエージェントに「パフォーマー」「批評家」「オーディエンス」の役割を与え、生成物に対する公開コミュニティ討論をソーシャルメモリとして蓄積・検索し、次ラウンドの生成コンテキストに注入することで、長文クリエイティブライティングの品質をラウンドごとに向上させる手法。

## このスキルを使うタイミング

- LLMで長文クリエイティブコンテンツ（コメディ、フィクション、脚本、説得的文章など）を複数ラウンドにわたって繰り返し生成し、品質を改善したい
- 単発プロンプトでは捉えられない「読者の反応・受容」を生成プロセスに組み込みたい
- セルフリフレクション（自己批評）だけでなく、多様な視点からのフィードバックで出力を多角的に改善したい
- コンテンツのクラフト品質（構成・明瞭さ）と社会的反響（記憶に残る度合い、共有意欲）の両方を高めたい
- ベースライン（討論なし）との対照実験で、レセプションの効果を検証したい

## 前提知識

### 核心的知見: なぜコミュニティ討論が有効か

**マルチエージェント自体ではなく、フィードバックチャネルが本質。**
エージェント数を増やすだけでは改善効果は不安定になりうる。重要なのは「レセプション（受容反応）が生成され、記録され、再利用可能になるチャネル」が存在すること。単一エージェントの自己批評と異なり、多様なペルソナからの公開討論は視点の多様性を構造的に保証する。

**改善はラウンド横断の間接経路で発現する。**
パフォーマーはラウンド内で書き直さない。効果はすべて「前ラウンドのレセプション → メモリキュレーション → ベクトルDB格納 → 次ラウンドでの検索・コンテキスト注入」という間接経路で生じる。これにより、ラウンド内編集や自己批評との効果の混同を防げる。

### 期待される効果とトレードオフ

- **クラフト・明瞭さの向上が最も安定的**: 意図の一貫性、構成の論理性、言語の経済性が改善する傾向がある
- **社会的反響（記憶に残る度合い、共有意欲、信頼感）も向上する傾向がある**
- **トレードオフ: エッジの効いたスタイルへの偏り**: コミュニティ討論で強い反応を引き出す素材（攻撃的・自虐的表現など）が選択的に強化される。クラフト向上と攻撃的スタイル強度の間に正の相関が生じうる（経験則: ρ≒0.29）。クラフト向上と安全性の両方を達成できるケースは全体の20〜25%程度にとどまる傾向がある
- コンテンツモデレーションが重要な場面では、メモリ書き込み時のスタイルフィルタリング追加を検討する

## 全体フレームワーク

```
ラウンド t:

[Phase 0: 初期設定（初回のみ）]
  エージェント設計 / ペルソナ割当 / トピックリスト固定 / ベクトルDB初期化
       │
       ▼
[Phase 1: トピック配信]
  ホスト → 全パフォーマーにお題 x_t を配信
       │
       ▼
[Phase 2: パフォーマンス生成]
  各パフォーマーが1つのコンテンツを生成（ラウンド内リビジョンなし）
       │
       ▼
[Phase 3: コミュニティ討論]  ※ベースライン条件(g=0)ではスキップ
  3a. 批評家レビュー（構造化スコア＋批評）
  3b. オーディエンス投稿・反応
  3c. 自由対話（意欲スコア制御＋適応的スロットリング＋停止ルール）
       │
       ▼
[Phase 4: ソーシャルメモリ書き込み]
  高シグナルなレセプション → キュレーション → ベクトルDBに格納
       │
       ▼
[Phase 5: メモリ検索 & コンテキスト注入]（ラウンド t+1 の開始時）
  次のお題＋ペルソナで検索クエリ構成 → 関連レセプション取得
  → バウンデッドコンテキストとしてパフォーマーに注入
       │
       ▼
[Phase 6: 評価]（全ラウンド終了後）
  A/B強制選択 + 多次元ルーブリック（3軸15項目）で品質診断
  Benefit-Safetyトレードオフの可視化
```

## 各フェーズの詳細

### Phase 0: 初期設定

#### エージェント構成

| 役割 | 推奨数 | 役割の本質 |
|------|--------|-----------|
| ホスト | 1 | トピック配信・進行制御 |
| パフォーマー | 3〜5 | コンテンツ生成者（比較評価のため複数） |
| 批評家 | 2〜3 | 構造化レビュー（スコア＋根拠付き批評） |
| オーディエンス | 15〜30 | 多様な反応・自由対話の担い手 |

合計30〜40エージェントが目安。

#### ペルソナ設計の原則

- 各エージェントに**固定のペルソナテキスト**（背景、好み、視点、社会的関係）を割り当てる
- ペルソナの目的は2つ:
  - (a) ラウンド間で一貫した行動を維持し、レセプション信号を解釈しやすくする
  - (b) 討論における視点の多様性を確保する（明示的なルール追加なしで実現）
- オーディエンスのペルソナには**対立する好みを意図的に含める**（例: 主流派 vs 実験派、保守的 vs 進歩的、技術寄り vs 感性寄り）
- エージェント間の**社会的関係**（友人、同僚、家族）を設定すると対話がより自然に展開する
- 批評家には異なる批評スタイル（理論重視 / 構造分析 / 商業的視点など）を持たせると、レセプションの多様性が増す

#### モデルとデコード設定

- **全エージェントに同一モデル・同一デコード設定を使用する**。これにより、条件間の差異をレセプションの有無のみに帰属させることができる
- 役割ごとに出力長の上限を設定する（パフォーマーは長文〜1,200語、オーディエンスは短文など）

#### トピック制御

- トピックリスト {x_1, ..., x_T} を事前に固定で生成する（推奨: T=50以上）
- 討論あり条件とベースライン条件で同一リストを再利用する

### Phase 1: トピック配信

ホストがラウンドtのトピック x_t をすべてのパフォーマーに配信する。全条件で同一トピックを使うことが実験統制の基盤。

### Phase 2: パフォーマンス生成

各パフォーマーが固定順序でコンテンツを1つ生成する。

**なぜラウンド内リビジョンを禁止するか:**
セルフリフレクション/リビジョンステージを追加すると、コミュニティフィードバック vs 自己批評の効果が混同される。品質改善がラウンド横断のレセプションフィードバックに起因することを保証するため、ラウンド内での書き直しは行わない。

### Phase 3: コミュニティ討論

レセプション生成の核心部分。3ステップで構成する。

#### 3a: 批評家レビュー
批評家エージェントが各パフォーマンスに対して構造化レビューを生成する。レビューには数値スコアと自然言語の批評を含める。

#### 3b: オーディエンスの投稿
オーディエンスエージェントがパフォーマンスまたは批評家レビューに対して投稿・反応を生成する。

#### 3c: 自由対話
エージェント駆動の自由対話フェーズ。以下の仕組みで制御する。

**意欲スコアによる参加制御:**
- 各対話ステップsで、全エージェント（ホスト除く）にペルソナ、トピック、バウンデッドコンテキスト C(a, t, s) を提供
- 各エージェントが意欲スコア w ∈ [0, 1] と返信先（任意）をJSON出力
- 意欲が低い場合は空の内容を出力してよい

**適応的スロットリング（推奨パラメータ: Kmax=5, 閾値=0.7）:**
- 意欲スコアが閾値（0.7）以上のエージェントから上位Kmax件を選択し発言許可
- 残りのエージェントはそのステップでは沈黙
- 同点はエージェントID等で決定的に解決

**停止ルール（以下のいずれかで終了）:**
- (a) 自由対話イベント数が上限に達する（推奨: 150イベント）
- (b) 連続して発言者ゼロのステップが一定回数続く（推奨: 15回連続沈黙）

**スレッド構造の構築:**
レセプションイベントをスレッド単位でグループ化する。スレッドIDの割り当て優先順位:
1. 明示的スレッドID指定あり → そのスレッドに帰属
2. 返信先エージェントのみ指定 → 同ラウンド内で返信先の直近イベントのスレッドを継承
3. いずれもなし → 新規スレッドを開始（新規UUID）

### Phase 4: ソーシャルメモリ書き込み

#### キュレーション（高シグナル選別）
ラウンド終了後、生のイベントログから以下の基準で高シグナルなアイテムを選別する:
- 明示的な批評・アドバイス
- 繰り返し現れる称賛や不満
- 簡潔なスレッド要約

#### 格納形式
各メモリアイテムを以下の形式でベクトルDBに書き込む:
- **テキスト本文** m
- **埋め込みベクトル** v
- **メタデータ**: 種類（批評家レビュー / オーディエンス投稿 / 自由対話）、ラウンド番号、対象パフォーマー
- **重要度スカラー** π

ベースライン条件（g=0）では討論がスキップされるため、メモリストアは空のまま。

### Phase 5: メモリ検索 & コンテキスト注入

#### 検索スコアリング
パフォーマーのコンテキスト構築時に、以下のスコアでメモリアイテムをランキングする:

```
Score(m) = λ × cos(q, v) + (1 − λ) × π + γ × Recency
```

- **q**: 現在のトピック＋エージェントペルソナ＋役割アンカーから構成したクエリ埋め込み
- **cos(q, v)**: クエリとメモリアイテムの意味的類似度
- **π**: 重要度スカラー
- **Recency**: 時間的な新しさ（新しいほど高い）
- **λ, γ**: 重み付けハイパーパラメータ（ドメインに応じて調整）

上位k件を取得する（推奨: k=30）。

#### バウンデッドコンテキストビルダー
パフォーマーに提供するコンテキスト C(a, t) は以下3要素を連結して構成する:

1. **役割アンカー**: 現在のトピック x_t（＋対象パフォーマンスやスレッドがあればそれも）
2. **短期バッファ**: 関連スレッドの直近L件の発言（推奨: L=10）
3. **検索済みコミュニティメモリブロック**: 取得したメモリアイテムを固定トークン予算内に収める（推奨: メモリブロック上限Bmem=1,600トークン、文境界で切断）

**なぜトークン予算を設けるか:**
LLMは長いコンテキストの中間部分を十分に活用できないという既知の制約がある。バウンデッドインターフェースにより、情報過多を防ぎつつ重要なレセプション信号を集中的に提供する。

### Phase 6: 評価

#### 評価設計の原則
- **A/B強制選択 + 多次元ルーブリックを併用する**: 全体的好みだけでなく、具体的にどの品質が改善したかを診断する
- 全体好みは主観が強く評価者間一致度が低くなりやすい（経験則: Fleiss' κ≒0.24程度）ため、ルーブリックベースの差分スコアを主要指標とする（経験則: ICC(3,5)≒0.71程度を期待）
- LLM生成物の評価にLLMジャッジを使うと相関エラーや自己評価バイアスが生じるため、人間評価を推奨

#### 推奨する評価軸（3軸15項目）

**軸1: アウトカム & クラフト（Q1〜Q6）**
- 即座の面白さ/効果
- リフレーミング・洞察
- 意図の明確さ
- 着地の正当性（伏線と結末の一貫性）
- 異化効果（馴染みのあるものを新鮮に見せる表現）
- 言語の技巧（文の経済性、リズム、ペーシング）

**軸2: スタイル分類（Q7〜Q10）**
- 親和的スタイル（関係性を強化する表現）
- 自己高揚的スタイル（自己を高める表現）
- 攻撃的スタイル（他者を犠牲にする表現）
- 自虐的スタイル（自己を犠牲にする表現）

※ スタイル項目は「高い＝良い」ではない。攻撃的・自虐的の増加はリスク増を意味しうる。

**軸3: 社会的フレーミング & 下流インパクト（Q11〜Q15）**
- 価値判断圧力（読者に道徳的判断を迫る度合い）
- 記憶に残る度合い
- 共有意欲
- 社会的魅力（話者の好感度）
- タスク魅力（話者の能力への信頼）

#### ブラインド化とランダム化
- 各ペアでA/Bの割り当てをランダム化する
- アイテムの提示順序をシャッフルし、連続ラウンドを隠す（学習効果・疲労効果の排除）

#### Benefit-Safetyトレードオフの可視化
改善効果と安全性のトレードオフを定量的に把握する:

```
Benefit = 平均( z(∆面白さ), z(∆クラフト), z(∆下流インパクト), z(∆好み) )
Safety  = − 平均( z(∆価値判断圧力), z(HarmShift) )

HarmShift = 平均(∆攻撃的, ∆自虐的) − 平均(∆親和的, ∆自己高揚的)
```

z-scoreで標準化し散布図で可視化する。「win-win象限」（Benefit≥0 かつ Safety≥0）のケース割合を確認することで、品質向上と安全性確保の両立度合いを評価できる。

## 制限事項と注意点

1. **単一モデル依存**: 全エージェントが同一モデルの場合、モデル固有のバイアス（ユーモア生成の癖、表現の偏りなど）が討論内容に反映される。異なるモデルファミリー（Claude, Llama, Geminiなど）やモデルスケールでの再現性は未検証であり、モデルごとに効果が異なる可能性がある。

2. **エッジ強化バイアス**: コミュニティ討論は強い反応を引き出す素材を選択的に強化する傾向がある。攻撃的・自虐的スタイルとクラフト向上の間に正の相関が生じうるため、コンテンツモデレーションが重要な環境ではメモリ書き込み時にスタイルフィルタリングの追加を検討する。

3. **文化的局所性**: ユーモアや創作の評価は文化・年齢層に強く依存する。特定の評価者プールで得られた結果を普遍的に一般化することはできない。評価者の多様性を確保し、文化的文脈を明示する。

4. **トピック依存性**: トピックの性質（難易度、討論条件との相性）によって優位性が変動する。十分な数のラウンド（50以上推奨）で効果を平均化し、ラウンドごとの変動も報告する。

5. **循環性リスク**: LLM生成テキストをLLMエージェントが評価する構造のため、モデルの好みが自己強化（エコーチェンバー化）する可能性がある。最終的な品質判断には必ず人間評価を使用する。

6. **シミュレーション規模**: 50ラウンド×5パフォーマー=250モノローグ規模での検証に基づく。より長期のシミュレーションやトピック多様性の拡大で、追加的なダイナミクスが現れる可能性がある。

## 発展的応用

### 他のクリエイティブドメインへの適用

コアアーキテクチャ（エージェント構成、討論→メモリ→検索→注入のパイプライン）は維持したまま、**レセプション抽象化層**を対象ドメインに合わせて調整する。具体的には、メモリフィルタと検索基準をドメイン固有の高シグナルフィードバック単位に修正する:

| ドメイン | レセプションで重視すべき信号 |
|---------|------------------------|
| フィクション | 物語の一貫性、キャラクターの声 |
| 脚本 | ペーシング、シーン転換の流れ |
| 説得的文章 | 知覚される信頼性、スタンスの整合性 |
| 教育コンテンツ | 理解度、エンゲージメント |
| SNSコンテンツ | 共有意欲、エンゲージメント率 |

### 安全性の強化方向

- メモリ書き込み時にスタイル分類器を追加し、攻撃的/自虐的コンテンツの重要度スカラーπを下げる
- パフォーマーのプロンプトにスタイルバランスの制約を明示する
- Benefit-Safety散布図からPareto最適点を分析し、両立パターンをテンプレート化する

### 異種モデル構成の探索

- パフォーマーと批評家に異なるモデルファミリーを使用し、モデル固有バイアスの自己強化を軽減する
- モデルスケールの違い（大型モデル for 批評家、軽量モデル for オーディエンス）によるコスト最適化の探索

本スキルは、マルチエージェントサンドボックスにおけるコミュニティ討論が長文クリエイティブ生成に与える影響を対照実験で検証した研究に基づく。以下の研究領域の知見を統合している:

- **エージェントベースの社会シミュレーション**: メモリ・リフレクション機構を持つ生成エージェントの設計パターン（Generative Agentsの系譜）
- **計算論的ユーモア**: LLMによるユーモア生成・理解の評価手法、短文ジョーク vs 長文モノローグの品質差
- **マルチエージェント創作支援**: ライターズルーム、ディレクター・アクター・ダイナミクス等の協調的創作フレームワーク、および「マルチエージェントが常に単一エージェントに勝るわけではない」という知見
- **ユーモアスタイル理論**: 親和的・自己高揚的・攻撃的・自虐的の4分類に基づくスタイル評価枠組み
- **読者反応理論**: 意図の知覚と説明的正当化を分離可能な受容次元としてモデル化する文学理論、異化効果（馴染みを新鮮にする表現技法）
