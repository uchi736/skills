# マルチエージェント時系列異常検知システムの構築

単変量時系列の異常を、人間の専門家のように「統計・トレンド・季節性・パターン変化」の
複数視点から並行して分析し、各視点の証拠を統合して信頼度つきの異常診断を生成する
LLMマルチエージェントシステムを設計・実装するためのレシピ。

単一の汎用LLMに長い数値列を渡して異常インデックスを直接答えさせる方式の限界
（長い数値入力の制御困難、正確な統計演算の苦手、複数時間視点の同時推論の難しさ）を、
**役割分解 ＋ 専用数値ツール ＋ 証拠の構造化統合**で乗り越える。

---

## このスキルを使うタイミング

- 異常スコアだけでなく、**異常タイプ・根拠・推奨アクションを含む診断**を出力したい
- 検知感度を後から閾値で調整できる（信頼度ベースの）運用をしたい
- ラベル付き異常データが乏しく、正常データから異常検知の参照例を作りたい
- 産業モニタリング・AIOps・Webサービス指標など、異種の異常が混在する運用時系列を扱う
- LLM単体プロンプトでの異常検知の精度・解釈性に限界を感じている

**向かないケース**: 多変量時系列（このスキルは単変量前提）、超低レイテンシ要求
（1ウィンドウあたり複数回のLLM呼び出しが必要なため）、極めて単純で反復的な
単一種類の異常だけを扱う場合（専門化の利得が小さい）。

---

## 前提知識（なぜこの設計が有効か）

このスキルの核心は、論文のアブレーション実験から読み取れる
**「どの構成要素が、どのデータ特性で効くか」** という判断知識にある。
これを理解せずに実装すると、不要なコストをかけたり、効く要素を削ったりする。

### 設計の4本柱と、それぞれの効き方

| 構成要素 | 役割 | 効く局面（経験則） |
|---------|------|-----------------|
| マルチアナライザ専門化 | 異常ファミリーごとに別エージェント | 異常タイプが多様・混在するデータで効果大。単純・反復的な異常では利得は小さい |
| 数値ツール拡張 | LLMの数値・統計演算の弱点を補う | 多様な異常が共存するデータで効果最大。LLMプロンプト単体では精度が出ない |
| マルチモーダル（可視化） | 図をVLMに渡し視覚証拠を得る | 運用時系列の微妙なパターン変化の捕捉に効く |
| 合成ICL（正常データ由来） | 正常↔異常の対比参照を文脈提供 | 長い系列で効果大。ただしアーキテクチャ自体ほど本質的ではない |

**最重要の知見**: 性能はこれら要素の「相互作用」で決まり、相対的重要度はデータ特性で変わる。
たとえば多様な異常が共存するデータではツールと専門化の寄与が支配的になり、これらを外すと
点単位F1が大きく劣化する。一方、運用系の単調なデータでは可視化や合成ICLの寄与が相対的に
大きくなる。**「全部入れれば全部のメトリクスが上がる」わけではない**ことに注意する。

### 「検知」と「診断」を分ける思想

多くのLLM異常検知は異常インデックス／区間を直接出力するため、ユーザーが感度を調整したり
根拠を点検したりできない。このスキルでは各異常候補に**連続値の信頼度**を付与し、検知を
「調整可能な診断プロセス」にする。ユーザーは閾値で偽陽性／偽陰性のトレードオフを制御しつつ、
裏付け証拠と異常タイプ予測を点検できる。

## 全体フレームワーク

```
┌─────────────────────────────────────────────────────────────┐
│ 5段階階層パイプライン（並列実行はLangGraph等のワークフローで）        │
└─────────────────────────────────────────────────────────────┘

[1. 入力] 単変量時系列 X = (x1, …, xn)
            │
            ▼
[2. 表現]  二重表現戦略（Dual Representation）
            ├─ 原系列（float精度）……… 数値ツール用
            └─ 圧縮サマリ（整数丸め＋統計量）… LLMプロンプト用（トークン~75%削減）
            │
            ▼
[3. マルチアナライザ] 4専門アナライザを並列実行（各々が専用ツール＋診断可視化で証拠生成）
            ├─ Point   : 大域/文脈的な点異常       （統計・外れ値・ローリング統計）
            ├─ Struct  : トレンド/平均/分散の変化   （分解・差分・変化点・区間比較）
            ├─ Season  : 振幅/周期性の異常          （ACF・FFT・ウェーブレット・STFT）
            └─ Pattern : パターン偏移/波形歪み      （SAX・リカレンスプロット・GAF・MTF）
            │  ※異種の出力を「候補区間・候補タイプ・要約・ツール出力」の共通形式に変換
            ▼
[4. Detector] 証拠統合（standalone検知ではなく、4アナライザの証拠を統合するのが主務）
            ├─ 各候補区間に 0–100 の証拠強度スコア → [0,1]に正規化
            ├─ ルーブリック: 偏差の大きさ・統計的有意性・アナライザ間の一致・矛盾の有無
            └─ 合成ICL（オフライン構築・オンライン検索）が信頼度スコアとタイプ順位付けを支援
            │  出力: {開始, 終了, 信頼度, 候補タイプ集合, 診断証拠}
            ▼
[5. 診断]  Supervisorエージェントがアナリスト向けレポートに変換
            └─ アラートレベル・時系列特性・アラーム根拠・推奨アクション

┌─────────────────────────────────────────────────────────────┐
│ 合成ICLサブシステム（Detectorを支援）                              │
├─ オフライン: 正常参照窓 → 代表部分列抽出(k-medoids) →             │
│              ルールベース異常注入(9種) → 対比ペアDB               │
└─ オンライン: 入力窓 → DTW検索(top-k=3) →                         │
              アナライザ提案タイプで参照選択 → Detectorへ            │
```

各段階の本質は「生の時系列への直接推論」を避け、**異常ファミリーごとに役割を分け、
定量的証拠と視覚的証拠を共通の枠組みに集約する**こと。単にLLMを並列化するのではない点に注意。

## 各フェーズの詳細

### フェーズ2: 二重表現戦略

**何をするか**: 入力時系列を2つの表現に分ける。

- **原系列**: float精度のまま保持し、すべての数値ツール計算に使う。
- **圧縮サマリ**: LLMプロンプト用。長さ・レンジ・平均・標準偏差・区間レベル統計を記録し、
  代表インデックスを一様ストライドでサンプリング、大域の最小・最大インデックスを補完する。
  サンプル値は整数に丸めてトークンを節約する（ツール計算は常に元のfloat値を使う）。

**なぜか**: 長い時系列をLLMに直接渡すとトークンコストが激増する一方、数値ツールは正確な
元値を必要とする。両者を分離することで、数値的忠実性を犠牲にせずLLM入力長を削減できる。

**具体的な設定（目安）**:
- デフォルト入力ウィンドウ: 400点、ストライド: 400
- 圧縮プロンプト予算: エージェントの役割に応じて 200–500 推定トークン程度
- 400点入力で約75%のトークン削減が期待できる

### フェーズ3: マルチアナライザシステム

**何をするか**: 9つの異常タイプを4つの異常ファミリーにグルーピングし、各ファミリーに
専門アナライザを1つ割り当てる。各アナライザは原系列と圧縮表現を受け取り、ファミリー固有の
分析結果（外れ値インデックス、変化点、スペクトル要約、リカレンスパターン、可視化由来の診断等）
を生成する。

**なぜグルーピングするか**: 局所的逸脱・レジームレベル変化・周期的撹乱・形状レベル歪みは、
それぞれ必要とする「証拠パターン」が異なるため。各アナライザは自分の担当タイプ**のみ**を扱い、
他ファミリーの分析には踏み込まない（役割の厳格な分離が診断の粒度を上げる）。

#### 4アナライザの担当範囲と主要ツール

各アナライザには「主要ツール（P）」と「共有補助ツール（S）」を割り当てる。
補助ツール（特にGAF・MTF・リカレンスプロット・記号表現）はマルチモーダルな補完証拠を提供する。

**PointAnalyzer（点異常 / タイプ1・2）**
- 担当: 大域点外れ値（大域分布から強く逸脱）、文脈的点外れ値（局所文脈で異常）
- 主要ツール: 基本統計（平均・標準偏差・歪度・尖度）、Z-score/IQRベースの外れ値検出、
  マルチスケールローリング統計
- 補助: SAX記号表現、リカレンスプロット
- 手順: 大域統計→外れ値候補抽出→ローリング統計で文脈異常→各候補をタイプ1/2に分類
- 図が与えられたら、候補点が周囲から本当に突出しているかを視覚的に確認する

**StructAnalyzer（構造変化 / タイプ5・6・7）**
- 担当: トレンド変化（傾き・長期方向の変化）、平均変化点（持続的なレベルシフト）、
  分散/スケール変化
- 主要ツール: STL分解、1次/2次差分、CUSUMベース変化点検出、区間レベル統計比較
- 補助: GAF（VLM）、リカレンスプロット
- 手順: 分解→差分でトレンド分析→変化点検出→変化点前後の区間比較
- 設計上の強み: このファミリーはタイプ一致度が最も高くなる傾向（変化点検定と区間比較が
  構造変化を確実に捉えるため）

**SeasonAnalyzer（季節性・周波数 / タイプ3・4）**
- 担当: 振幅変化（周期的パターンの大きさの変化）、季節性異常（周期構造・支配周波数の撹乱）
- 主要ツール: 分割半ACF比較、FFT、ウェーブレット変換、STFT
- 補助: SAX、リカレンスプロット、MTF（VLM）
- 手順: ACFで支配周期検出→FFTで周波数領域分析→ウェーブレットで時間-周波数局在→
  期待vs観測の季節パターン比較
- 注意（重要な弱点）: 周波数領域ツールは**正確な点単位の局在化が苦手**で、このファミリーは
  検出リコールが最も低くなる傾向。ただし季節変化の診断手がかりとしては有用

**PatternAnalyzer（パターン / タイプ8・9）**
- 担当: パターン偏移（反復パターンの形状/位相の変化）、波形歪み（反復波形の形状の歪み）
- 主要ツール: SAX記号表現、リカレンスプロット、GAF（VLM）、MTF（VLM）
- 補助: ローリング統計、ACF
- 手順: SAXでパターン反復と破断を分析→リカレンスプロットでレジーム遷移・決定性変化→
  ACFで反復周期確認→ローリング統計で局所変化→全証拠を統合
- 主要指標: SAXパターン破断（記号列の急変）、リカレンスプロットの低決定性/低ラミナリティ
  （パターン構造の喪失）、ACF周期変化、局所分散スパイク
- 注意（重要な弱点）: 検出リコールは高い（異常領域は局在化できる）が、**パターン偏移と
  波形歪みの区別**が最終タイプ決定段階で難しく、タイプ一致度が低くなる傾向

#### 共通形式への変換

Detectorでの統合のため、異種のアナライザ出力を共通の証拠表現に変換する。
最低限含めるフィールド: 候補位置/区間、候補異常タイプ、分析要約、裏付けツール出力。
これによりDetectorはファミリー横断で証拠を比較しつつ、ファミリー固有の診断情報を保持できる。

### フェーズ4: 証拠統合Detector

**何をするか**: アナライザ出力と診断可視化を統合し、異常区間・信頼度スコア・異常タイプを生成する。
Detectorの主務は**生の数値列から独立に異常検知することではなく、4アナライザの証拠を統合すること**。
可視化は定量出力を補完しアナライザ支持候補を検証する「証拠アーティファクト」として扱う。

**信頼度スコアリングの設計**:
- LLMに証拠強度を 0–100 の整数で評価させ、[0,1]に正規化する
- ルーブリックが考慮するもの: 偏差の大きさと統計的有意性、アナライザ間の一致、矛盾証拠の有無
- 証拠が衝突する場合: 強いツール出力とアナライザ間一致に支持される候補を優先し、
  支持が弱い/孤立した候補は信頼度を下げる
- **重要**: スコアは「一致したアナライザの単純な数」ではなく**証拠の質と一致度**を反映する。
  較正された異常確率ではなく、順序的な証拠強度バンドであることを明確に意識する

**スコアバンドの設計指針（自分の言葉で実装する）**:
- 明確に正常な変動 → 最低帯（異常として出力しない）
- 弱い証拠（軽微な逸脱・曖昧な視覚パターン）→ 低帯
- 境界的（ノイズの可能性がある小さな孤立逸脱）→ 中低帯
- 明確な異常（顕著なスパイク/ディップ、z>2、構造変化）→ 中帯
- 強い証拠（背景の2倍以上の大きさ、複数点クラスタ）→ 中高帯
- 圧倒的（極端な大きさ、複数ソースで確認）→ 最高帯

**スコアリング規則**:
- スコアはz-scoreの数値そのものではなく**証拠の明確さ**を反映する
- z-scoreより「実際の値 vs 背景レンジの大きさ」を重視する
- スパイククラスタ加点: 連続2点以上で中帯下限、3点以上で中高帯下限を確保
- 一定スコア未満（例: 50未満）の異常は出力しない
- インデックス精度が重要: ツール報告のインデックスを直接使う
- アナライザ候補を超えて、データや図が見逃し異常を示すなら報告してよい

### フェーズ4補助: 合成ICL（正常データからの文脈学習）

**核心アイデア**: 実際の異常区間や異常タイプラベルに依存せず、**正常データから生成した
正常↔異常の対比参照**でDetectorを支援する。二値ラベルは「参照プールから異常区間を除外する」
目的にのみ使い、実異常デモンストレーションやタイプ教師として使わない。

**オフライン: 合成ICLデータベース構築**
1. **代表部分列抽出**: 各訓練系列を固定長部分列に分割し、ラベル付き異常区間と重なる部分列を
   除外。残った正常参照部分列にk-medoidsクラスタリングを適用。
   - medoid数はシルエットスコアで k ∈ [2, min(20, ⌊N/2⌋)] から選択
   - 部分列が12個以下ならクラスタリングせず全保持
   - k-medoidsを使う理由: 平均化セントロイドではなく**実観測された部分列をそのまま
     プロトタイプとして保持**できるため
2. **ルールベース異常注入**: 各正常プロトタイプに9タイプの摂動を注入（後述の注入ルール）。
   注入位置・大きさは有界範囲でサンプリングし、ベース正常パターンを保ちつつ意図したタイプを表現
3. **対比ペア構築**: 各プロトタイプにつき9タイプそれぞれ1例ずつ生成（タイプ完備でバランス）。
   各ペアに正常部分列・注入異常部分列・タイプラベル・ツールベース証拠要約
   （統計変化・変化点応答・スペクトル変化・ACF変化・区間比較）を格納

**オンライン: 検索**
1. 入力系列とDB内の代表正常プロトタイプをDTW（局所的時間ずれに頑健）で比較。
   LB_Keoghプルーニングで不要比較を削減し、top-k=3の最類似プロトタイプを選択
2. それらの対比参照から、**アナライザが提案した候補タイプに応じて**参照を選択しDetectorへ提供
   - 注意: アナライザ予測タイプは「プロトタイプ検索後の参照選択」に使い、
     DTW類似度計算そのものには使わない
   - 検索・参照選択はテストセット正解・真の異常タイプ・実異常区間を一切使わない

**なぜ有効か**: 他ファイルの実異常区間に依存する検索ベースICLと違い、正常プロトタイプから
合成した対比参照を使うため、実異常ICL例への依存を減らしつつ、信頼度スコアリングと
タイプ診断のための対比証拠をDetectorに供給できる。ゼロショット（合成ICLなし）でも
コア・アーキテクチャ（専門化＋ツール＋証拠統合）だけで強い性能が出る点が、この設計の
本質的価値を示している。

### フェーズ5: Supervisor診断レポート

**何をするか**: 構造化された異常レコードと裏付け証拠を、アナリスト向け診断レポートに変換する。
**Detector出力とアナライザ証拠を超えて、新しい異常区間・タイプ・根拠のない原因を導入しない**。

**レポートに含めるフィールド**:
- エグゼクティブサマリ: 異常の有無・深刻度・即時対応要否を1–2文で
- 時系列特性: 全体トレンド・季節性・データ品質・特徴・正常レンジ・変動性
- 確定異常: 各異常の位置・タイプ・説明・信頼度・深刻度・影響範囲
- 総合アラートレベル: 事前定義のアラームレベル基準で判定
- アラーム根拠: アラートレベル判定の理由
- 推奨アクション: Urgent/Errorケースの即時対応・モニタリング戦略・追加分析提案

## 9つの異常タイプと合成注入ルール

合成評価セットと合成ICLデータベースの構築に使う。タイプが隣接しうる場合は
「支配的な変化モード」で代表ラベルを割り当てる（局所孤立逸脱→点、平均/分散/トレンドの
持続変化→構造、反復構造の変化→季節、形状レベル歪み→パターン）。

注: σ は正常プロトタイプの標準偏差、n は系列長。

| # | タイプ | ファミリー | 注入ルール（パラメータの目安） |
|---|--------|----------|---------------------------|
| 1 | 大域点異常 | Point | ランダム位置に孤立スパイク/ドロップを1–3個、大きさ 5σ |
| 2 | 文脈的点異常 | Point | 局所窓 max(10, n/20)、大きさは局所標準偏差の3倍 |
| 3 | 振幅変化 | Season | 周期セグメントの後半の平均からの偏差を係数2.0でスケール（周波数は保持） |
| 4 | 季節性異常 | Season | 後半周波数を係数2.5で変更、または後半振幅を元偏差の15%に平坦化しノイズ(0.15σ)付加 |
| 5 | トレンド変化 | Struct | 0.5n から傾き max(0.05σ, 0.05) の線形ドリフト付加（既存強トレンド時は方向反転） |
| 6 | 平均変化点 | Struct | [0.4n, 0.6n] で変化点をサンプリングし、後半を 1.5σ シフト |
| 7 | 分散変化 | Struct | [0.4n, 0.6n] で変化点をとり、後半の平均からの偏差を 2.0 or 2.5 でスケール |
| 8 | パターン偏移 | Pattern | 後半を検出周期の1/4だけ循環シフト |
| 9 | 波形歪み | Pattern | [0.4n, 0.7n] を局所平均 ±0.5×局所標準偏差 にクリップ |

## ツールパラメータの推奨設定

データセット間で固定し（ウィンドウ長や自動検出周期から推論する場合を除き）、
データセットごとにチューニングしない方針。

| ツール | パラメータ |
|--------|----------|
| 外れ値検出 | Z-scoreしきい値 3.0、IQR乗数 1.5 |
| ローリング統計 | マルチスケール局所窓、文脈候補の局所Z-scoreしきい値 2.5 |
| 分解 | 未指定時はFFTで周期自動検出、移動平均またはSTL系分解 |
| SAX / MTF | アルファベット/ビンサイズ 10 |
| リカレンスプロット | 近傍パーセンタイル 0.1 |
| STFT | 窓サイズ 64、ホップサイズ 32 |
| レジーム拡張 | 50点検証チャンク、100点参照窓、平均/分散差検定 p < 0.05 |
| 全般 | temperature 0.0（決定的出力）、合成ICL検索 top-k=3 |

**temperatureを0.0にする理由**: 確率的サンプリングは点単位の信頼度スコアと異常インデックス
予測に不要な分散を持ち込むため。決定的・再現可能な出力を確保する。

## 評価とスレッショルディング

**評価指標**（4つ併用を推奨）:
- Point-F1: 点単位の検出精度。**正確な局在化と偽陽性に最も敏感**
- PA-F1（点調整F1）: 緩和されたセグメントレベル評価。粗い区間カバーを報酬しがち
- Affiliation-F1: 予測区間と正解区間の時間的近接性を考慮
- Delayed-F1（k=3）: 異常発生からk時間ステップ以内の最初の予測を検出とみなす早期検出評価

**メトリクス解釈の注意**: PA-F1・Affiliation-F1・Delayed-F1のような緩和メトリクスは粗い
区間カバーでも高く出ることがある。マルチアナライザ専門化は「全メトリクスの一様改善」では
なく、**正確な局在化と診断粒度の改善**として解釈する。実際、単純・反復的な異常では単一
アナライザでも粗い局在化は維持され、緩和メトリクスは専門化を外しても下がりにくい
（むしろ僅かに上がることすらある）。

**スレッショルディングの重要な教訓**:
- 信頼度は順序的な証拠強度スコアであり、確率較正された出力ではない。
  分布はデータセット・ウィンドウ間でシフトする
- **固定グローバル閾値は不安定な時系列環境では不十分**。固定閾値は全データセットで性能が
  大きく劣化し、特に運用系データで顕著
- 評価では post-hoc Best-F1 閾値探索を「スコア識別能の推定（評価専用プロトコル）」として使う。
  正解ラベルを評価にのみ使うため、これはデプロイ可能な閾値戦略ではない
- **実デプロイでは較正または検証セットでの閾値選択が必要**。SAGEの実務価値は信頼度スコア
  単体ではなく、構造化証拠・異常タイプ情報・自然言語説明にあり、これらが実務者がドメイン知識
  で運用閾値を選ぶ助けになる

## 実装メモ

- **ワークフロー基盤**: LangGraph系のワークフローで4アナライザを並列実行する構成が素直
- **バックボーン選択（経験則）**: 推論能力・構造化出力の安定性・コスト効率のトレードオフを評価する。
  比較した範囲では、強い推論能力と安定した構造化出力を持つフロンティアモデルが3データセットで
  最も一貫した性能を示した。小型モデルは点単位F1・PA-F1で苦戦し、構造化推論の精度が不足する
  傾向（粗い時間的近接は保てることがある）。バックボーンは差し替え可能だが、構造化出力の
  安定性が全体性能を左右する
- **コスト感覚の目安**: 1ウィンドウ（400点）あたり、強力なフロンティアモデルで入力~22K
  トークン・出力~5Kトークン規模、処理時間は数十秒オーダー。**1ウィンドウに複数回のLLM
  呼び出しが必要**な点がコスト・レイテンシの主要ボトルネックになる
- **オープンモデルを使う場合**: vLLM等でのサービングを検討。テンソル並列でスループットを確保

## 制限事項と注意点

- **単変量限定**: 多変量時系列には未対応。複数信号にまたがる異常は単一の単変量信号から
  完全には観測できない
- **コストとレイテンシ**: ウィンドウあたり複数回のLLM呼び出しが必要で、これが主要な実務的
  ボトルネック。低レイテンシ・低コスト要求の用途には不向き
- **合成摂動の限界**: ルールベース注入はすべての実世界の故障モードをカバーできない。特に
  原因が完全には観測できないシステム固有の微妙な異常は再現しにくい
- **タイプ識別の弱点**: パターン偏移と波形歪みの区別は最終タイプ決定段階で難しい
  （検出はできても正しいタイプを当てにくい）。季節性異常は正確な点単位局在化が苦手
- **信頼度は確率ではない**: 順序的な証拠強度スコアであり、そのまま確率として扱えない。
  デプロイには較正が必要
- **過信のリスク**: 診断を自律的判断として安全クリティカルな場面で使うと、偽陽性が不要な
  介入を、偽陰性が実インシデントへの対応遅延を招きうる。意思決定支援として枠づける

## 発展的応用

- **適応的な第1段フィルタリング**: 明らかに正常なウィンドウを軽量な前段で除外し、
  高コストなマルチアナライザ処理を異常可能性の高いウィンドウに集中させてコストを下げる
- **多変量への拡張**: 信号間の相互作用を扱うアナライザの追加や、信号横断の証拠統合
- **細粒度局在化の改善**: パターン（偏移vs歪み）と季節性の点単位局在化精度の向上
- **デプロイ志向の較正**: 検証セットベースの閾値選択、信頼度の確率較正、ドメイン知識に
  基づく運用閾値の設計
- **アナライザ／ツールの拡張**: 新しい異常ファミリーを定義し、対応する専用ツール群と
  注入ルールを追加することで、共通の証拠統合フレームワークを保ったまま検知範囲を広げる
