# 経験駆動型 生涯学習エージェントの設計パターン

対話履歴から成功パターンを抽出し、スキルとして体系化し、
モデルのパラメータに内在化させることで、使うほど賢くなるエージェントを構築する方法論。

## このスキルを使うタイミング

- 複数セッションにまたがる長期的なやりとりを行うエージェントを設計するとき
- エージェントが過去の成功・失敗体験から自律的に改善する仕組みを作りたいとき
- 静的なSFT（教師ありファインチューニング）だけでは対応しきれない、動的に知識が増える領域のエージェントを構築するとき
- 既存のRAGやメモリ機構だけでは不十分で、スキルの抽出・内在化まで踏み込みたいとき

## 前提知識

従来のLLMエージェントの多くは、学習後に固定される。プロンプト工夫やRAGで表面的に適応はできても、過去のやりとりから新しいスキルを抽出し、それをモデル自体に取り込む仕組みは持っていない。

一方、人間の専門家（カウンセラー、医師、コンサルタント等）は「経験駆動型のループ」で成長する。成功事例から実践的な勘所を抽象化し、それを自分の直感として内面化していく。

この設計パターンは、そのループを3つのエンジンで再現する。

1. 記憶増強型プランニングエンジン（縦断的な文脈の維持）
2. スキル進化エンジン（成功体験からの技法抽出）
3. 強化的内在化エンジン（抽出した技法のパラメータへの定着）

この3つは独立に機能するのではなく、閉ループとして連動する。セッション内ではエンジン1と2が即時推論を支え、セッション間ではエンジン3が最良の軌跡を選別してモデルを更新する。

## 全体フレームワーク

```
┌─────────────────────────────────────────────────────┐
│              セッション内ループ                        │
│                                                     │
│  ユーザー入力                                         │
│      ↓                                              │
│  [エンジン1] 記憶参照 + 戦略プランニング                  │
│      ↓                                              │
│  [エンジン2] スキルツリーから最適スキル検索                │
│      ↓                                              │
│  応答生成（思考連鎖 + スキル適用）                       │
│      ↓                                              │
│  記憶更新（プロファイル + セッション要約）                 │
│      ↓                                              │
│  次のターンへ / セッション終了                           │
└───────────────┬─────────────────────────────────────┘
                │ セッション終了時
                ▼
┌─────────────────────────────────────────────────────┐
│              セッション間ループ                        │
│                                                     │
│  [エンジン2] 成功セッションから新スキル抽出               │
│      ↓                                              │
│  スキルツリーへの追加 or 既存スキルとの統合               │
│      ↓                                              │
│  [エンジン3] 複数ロールアウトから最良軌跡を選択            │
│      ↓                                              │
│  棄却ファインチューニングでパラメータ更新                  │
│      ↓                                              │
│  次のセッションへ（進化したエージェントで対応）            │
└─────────────────────────────────────────────────────┘
```

## 各フェーズの詳細

### フェーズ1: 記憶増強型プランニングエンジンの構築

目的: セッションをまたいだ文脈の一貫性を維持する。単純なコンテキストウィンドウやRAGでは不十分なケースに対応する。

#### 1-1. 動的記憶ストアの設計

記憶を2種類に分けて構造化する。

進化するプロファイル: ユーザー（クライアント）の属性情報を動的に管理する。固定のインテーク情報ではなく、各セッション終了時に新しい属性を抽出して増分更新する。

```
更新後プロファイル ← Update(前回プロファイル, Extract(前セッションの対話))
```

設計判断のポイント: プロファイルは「上書き」ではなく「増分更新」にする。過去の状態も履歴として残すことで、変化のトレンドを追跡できる。

エピソード的セッション要約: 各セッションの要約を構造化して蓄積する。感情の変化、介入の結果、残された課題などを圧縮して記録する。

#### 1-2. 目標指向型の戦略プランニング

セッション開始前に、蓄積した記憶から今回のセッションの戦略を立案する。

プランに含めるべき情報:

- 現在のフェーズ（全体の進捗における位置づけ）
- 今回のセッション目標（具体的、実行可能なもの）
- 過去のセッションからの引き継ぎ事項

#### 1-3. 学習データの構築

記憶抽出・プラン推論・応答生成の3タスクそれぞれについて、入力→出力のペアを教師データとして構築し、SFTで学習させる。

```
学習損失 = -Σ log P(出力 | 入力)
              （記憶抽出データ + プラン推論データ + 応答生成データ）
```

経験則: 応答生成だけでなく、記憶抽出とプラン推論にも明示的な教師信号を与えることで、エージェントの構造的な判断能力が向上する傾向がある。

### フェーズ2: スキル進化エンジンの構築

目的: エージェントが持つ技法・戦略のレパートリーを、経験から自律的に拡張する。

#### 2-1. 階層的スキルツリーの設計

スキルを4階層のツリー構造で管理する。

- レベル1（ルートパラダイム）: 基盤となるフレームワーク（例: CBT、ヒューマニスティック療法。ドメインに応じて置き換える）
- レベル2（ステージ）: プロセスの大きなフェーズ（例: 問題把握、介入、定着）
- レベル3（メタスキル）: 各ステージ内の戦略カテゴリ（例: 共感構築、認知再構成）
- レベル4（アトミックスキル）: 1ターンで実行可能な具体的技法（例: ソクラテス式質問、比喩的リフレクション）

設計判断のポイント: 4階層が推奨される理由は、粒度が細かすぎると検索ノイズが増え、粗すぎると適切なスキル選択ができないため。ドメインの複雑さに応じて3〜5階層で調整する。

#### 2-2. 文脈依存型スキル検索

推論時に、現在の対話状態（ユーザー入力 + 記憶 + セッション目標）から最適なアトミックスキルを生成的に選択する。

```
最適スキル = argmax P(スキル | ユーザー入力, 記憶, セッション目標)
```

選択されたスキルは応答生成の入力に明示的に付加する（思考連鎖の一部として組み込む）。

#### 2-3. 生成的スキル進化

セッション終了後、成功した対話軌跡から新しいスキルを抽出する。

ターゲット型スキル抽出: セッション目標に最も関連するメタスキルを特定し、成功軌跡からそのメタスキルを具体化するアトミックスキルを抽象化する。

```
新スキル ← Extract(成功軌跡 | 関連メタスキル, セッション目標)
```

適応的スキル管理: 新スキルと既存スキルの意味的類似度を比較し、追加（新規ノードとして）か統合（既存ノードの洗練として）かを判断する。

```
if 新スキルが既存スキルと十分に異なる → 追加
if 新スキルが既存スキルの発展形 → 統合（定義を洗練）
```

この仕組みにより、冗長性を防ぎつつ既存技法の継続的な改良が可能になる。

経験則: 抽出されるスキルの多くは「まったく新しい技法」ではなく、「既存技法に実践的な詳細（閾値、テンプレート、モニタリングルール、最小実行単位）を追加したもの」になる傾向がある。これは正常な進化パターン。

### フェーズ3: 強化的内在化エンジンの構築

目的: エンジン2で外在的知識として蓄積されたスキルを、モデルのパラメータに内在化させる。外部検索への依存を減らし、直感的に高品質な応答を生成できるようにする。

#### 3-1. 反復的なロールアウトと選択

セッションレベルで探索を行う（トークンレベルのRLではない）。

- 並列ロールアウト: 各セッションについて、N個の候補セッションを並列生成する。各候補は異なるスキルの組み合わせや対話戦略を探索する。
- 報酬評価: 包括的な報酬モデル（LLM-as-a-Judge等）で各候補を評価する。
- 貪欲選択: 最高報酬の候補セッションを選択する。次のセッションの記憶更新は、この最良軌跡のみに基づいて行う。

推奨パラメータ: ロールアウト数 N=8 が良いバランスとされている。少なすぎると探索の多様性が不足し、多すぎると計算コストが膨らむ。

#### 3-2. 棄却ファインチューニングによる内在化

最良の生涯軌跡（各セッションで選択された最良候補の連結）を構築し、これをファインチューニングデータとして使用する。

```
学習損失 = -Σ log P(最良セッション | これまでの最良履歴)
```

低報酬の候補（棄却されたセッション）は暗黙的な負例として機能する。これにより、スキルや計画ロジックが徐々にモデルの重みに蒸留される。

設計判断のポイント: トークンレベルのRLではなくセッションレベルの棄却サンプリングを使う理由は、長期的に一貫した戦略を学習させるため。個々のトークンの最適化では、セッション全体の治療効果のような長期報酬を適切に最適化しにくい。

## チェックリスト

### 記憶エンジン構築時

- [ ] プロファイルは増分更新方式か（上書きではなく追加＋履歴保持）
- [ ] セッション要約は構造化されているか（自由文ではなく、感情変化・介入結果・残課題等のフィールドを持つ）
- [ ] 記憶抽出・プラン推論・応答生成の3タスクすべてに教師データがあるか
- [ ] プランには具体的なセッション目標が含まれるか

### スキル進化エンジン構築時

- [ ] スキルツリーは3〜5階層で設計されているか
- [ ] スキル検索は生成的（ルールベースではなく確率的選択）か
- [ ] 新スキル抽出時にセッション目標との関連付けを行っているか
- [ ] 追加 vs 統合の判断基準が定義されているか
- [ ] 冗長スキルの防止メカニズムがあるか

### 内在化エンジン構築時

- [ ] ロールアウトはセッションレベルで行われているか（トークンレベルではない）
- [ ] 報酬モデルは多面的な評価軸を持つか（単一スコアではない）
- [ ] 記憶更新は最良軌跡のみに基づいているか
- [ ] ロールアウト数は8前後か（4未満は探索不足、16超は非効率の可能性）

### 全体アーキテクチャ

- [ ] 3エンジンが閉ループとして連動しているか
- [ ] セッション内ループ（記憶＋スキル→応答）とセッション間ループ（スキル抽出＋内在化）が区別されているか
- [ ] 各エンジンのアブレーション評価を予定しているか

## 制限事項と注意点

### 既存メモリ機構との違い

汎用的なRAG、Graph RAG、Mem0、MemoryBankなどを強力なバックボーンLLMに接続しても、この設計パターンほどの改善は得られない傾向がある。理由として、専門的な長期対話では「事実の想起」だけでなく「変化する状態の追跡」「介入の根拠の把握」「過去の戦略判断の参照」が必要であり、汎用メモリだけではカバーしきれないことが挙げられる。

### 計算コスト

ロールアウト（N=8の並列生成）と棄却ファインチューニングは、推論・学習の両面で計算コストが高い。論文の実験ではH200 GPU 16枚（8枚×2サーバー）が使用されている。小規模な実験や予算が限られる場合、ロールアウト数を減らす（N=4等）か、内在化の頻度を下げるなどの調整が必要。

### スキル抽出の性質

抽出されるスキルはほとんどの場合「まったく新しい技法の発明」ではなく、「既存技法の実践的な詳細化」である。閾値の設定、テンプレートの具体化、モニタリング手順の追加、最小実行単位の定義などが典型的。これは限界ではなく、実務的に最も価値のあるタイプの進化と捉えるべき。

### スケーリングと汎用性

8Bパラメータのモデルでも3エンジンの効果は確認されており、モデルスケールだけに依存しない手法ではある。ただし、ドメインごとにスキルツリーの初期設計、報酬モデルの評価軸、教師データの構築が必要であり、ゼロショットでの転用はできない。

### 安全性

心理カウンセリング等のセンシティブなドメインでは、自己進化するエージェントの安全性とプライバシー保護が追加的な課題となる。自動評価だけに頼らず、人間の専門家による定期的な監査を組み込むことが推奨される。

## 発展的応用

### 他ドメインへの展開

この設計パターンは心理カウンセリングに限定されない。以下のような領域で同様のアプローチが有効と考えられる。

- 教育（チュータリング）: 学習者の理解度を記憶し、教授法スキルを進化させる
- コンサルティング: クライアントの事業状況を追跡し、助言戦略を洗練する
- カスタマーサポート: 顧客の履歴から対応パターンを抽出し、解決スキルを蓄積する
- コーチング: 長期的な目標追跡とアプローチの自律的改善

### スキルの領域横断的再利用

内在化後のモデルでは、ある領域で獲得した機能的スキルパッケージが他の文脈でも再利用される現象が確認されている。完全な汎用化ではないが、「目標→実践→記録」の橋渡しや「進捗の定着」「感情の安定化→深い探索」といった上位パターンは複数の文脈で横断的に機能する傾向がある。

### 人間評価との組み合わせ

自動評価（LLM-as-a-Judge）と人間の専門家評価は高い一致度を示す傾向があるが、倫理面や共感面では評価スタイルの差異が出やすい。自動評価はスケーラブルな補助評価器として位置づけ、人間評価を完全に代替するものとはしないのが安全。
