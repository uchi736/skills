# 二値質問による評価・自己改善 プロンプトテンプレート一式

元の論文は手法を文章で説明していますが、実際に使うプロンプトの全文は掲載していません（付録にあるのは、生成された質問の例と、更新後プロンプトの断片のみ）。以下は、論文の手順（要件抽出→二値質問化→独立評価→集計、および改善ループ）に忠実に再構成した、そのまま使えるテンプレートです。JSON出力に統一してあり、集計を機械的に回せる形にしています。

評価対象の文章がAIの出力か人間の執筆かは問いません。原文と要約、指示文と完成文など「入力と出力のペア」であれば適用できます。プロンプト内の言語は評価したい文章に合わせて差し替えてください（ここでは日本語）。

---

## パイプライン全体像

| ステップ | プロンプト | 入力 | 出力 | 頻度 |
|---|---|---|---|---|
| 質問生成 | テンプレート1 | タスク指示文 | 評価軸ごとの二値質問セット | タスク種別ごとに一度（使い回し可） |
| 評価 | テンプレート2 | 入力＋出力＋質問セット | 各質問のYes/No＋理由 | 出力1本ごと |
| 集計 | （コード or 手計算） | 評価結果 | 軸別・総合スコア | 出力1本ごと |
| 教訓抽出 | テンプレート3 | 失敗・不一致の記録 | 一般化された教訓 | 改善ループ時のみ |
| 重複統合 | テンプレート4 | 教訓の候補 | 重複を除いた教訓 | 改善ループ時のみ |
| プロンプト書換 | テンプレート5 | 現行プロンプト＋教訓 | 更新後プロンプト | 改善ループ時のみ |

最小構成はテンプレート1と2です。改善ループ（3〜5）は、評価器や生成側のプロンプトを自動で磨きたい場合のみ使います。

---

## テンプレート1：二値質問の生成（メタプロンプト）

タスク指示文を渡すと、評価軸ごとに整理された二値質問セットを返します。タスク種別（要約、対話応答、指示遵守など）ごとに一度実行し、得られた質問セットを保存して使い回します。

```
あなたは、生成タスクの品質評価基準を設計する専門家です。
以下のタスク指示文を分析し、出力の品質を検証するための二値質問（Yes/No質問）を生成してください。

【評価対象のタスク指示文】
{TASK_DESCRIPTION}

【任意：評価軸の指定】
{DIMENSIONS}
（指定がなければ、タスク指示文から適切な評価軸を自分で導出してください。
　例：一貫性、事実整合性、流暢さ、関連性）

【手順】
ステップ1：要件の抽出
上記のタスク指示文を、満たすべき要件のリストに分解してください。
各要件は、互いに独立した1つの評価観点を表すようにします。
（例：特定の情報が含まれているか、指定された書式を守っているか）

ステップ2：二値質問への変換
各要件を1つ以上のYes/No質問に変換してください。次のルールに従います。
- 「Yes」がその要件を満たしている状態、「No」が違反している状態を指すよう向きを統一する
- 1つの要件が複数の確認事項を含む場合は、質問を分ける
- 各質問に、「No」に該当する具体的な違反例を1つ添える
- 各質問を、いずれかの評価軸に割り当てる

【良い質問の条件】
- 1つの検証可能な性質だけを問う。複数の観点を1問に詰め込まない
- 判定がぶれにくい具体的な問いにする
  （悪い例：「事実整合性を高く保っているか」／良い例：「すべての固有名詞が原文どおりに表記されているか」）
- 同じ軸の質問どうしが、なるべく別々の失敗を拾うようにする
  （例：綴りを見る質問と句読点を見る質問は、重ならないよう独立させる）

【出力形式】
以下のJSONのみを出力してください。前置きや解説は不要です。
{
  "requirements": [
    {"id": "R1", "dimension": "評価軸名", "description": "要件の内容"}
  ],
  "questions": [
    {
      "id": "Q1",
      "dimension": "評価軸名",
      "source_requirement": "R1",
      "question": "Yes/Noで答えられる質問文",
      "violation_example": "Noに該当する具体例"
    }
  ]
}
```

## テンプレート2：二値評価（評価器）

入力・出力・質問セットを渡すと、各質問にYes/Noと理由を返します。評価対象の出力1本ごとに実行します。

```
あなたは、生成された出力を検証する評価者です。
以下の入力と出力を読み、与えられた各質問に独立に答えてください。

【入力（原文・文脈・指示など）】
{SOURCE_INPUT}

【評価対象の出力】
{OUTPUT}

【質問リスト】
{QUESTIONS}

【回答のルール】
- 各質問には、他の質問と切り離し、その質問だけを見て答える
- 判定は Yes（1）または No（0）のいずれか
- 各判定に、そう判断した理由を1文で添える
- 推測で補わず、入力と出力に実際に書かれている内容に基づいて判定する
- 出力に情報が「無い」ことと、出力の内容が「間違っている」ことを区別する
  （原文にある情報を省略しただけなら、事実の誤りとはしない。
　　出力に書かれていて根拠がない、または矛盾する記述だけを違反とする）

【出力形式】
以下のJSONのみを出力してください。
{
  "verdicts": [
    {"id": "Q1", "answer": 1, "explanation": "この判定にした理由（1文）"}
  ]
}
```

補足：`{QUESTIONS}` にはテンプレート1が出力した questions 配列を、`id` と `question` が分かる形で流し込みます。

## スコア集計

評価器の出力（verdicts）を集計してスコアにします。コードでも手計算でも同じです。

- 軸ごとのスコア：その軸に属する質問の answer の平均
- 総合スコア：全質問の answer の平均
- いずれも 0〜1 の範囲。既存の a〜b 点尺度に合わせたい場合は `スコア × (b − a) + a` で換算

参考実装（Python）：

```python
from statistics import mean

def score(verdicts, questions):
    dim = {}
    for q in questions:
        dim.setdefault(q["dimension"], []).append(0)
    id2dim = {q["id"]: q["dimension"] for q in questions}

    by_dim = {}
    for v in verdicts:
        by_dim.setdefault(id2dim[v["id"]], []).append(v["answer"])

    per_dimension = {d: mean(a) for d, a in by_dim.items()}
    overall = mean([v["answer"] for v in verdicts])
    return per_dimension, overall

def rescale(s, a=1, b=5):
    return s * (b - a) + a
```

## テンプレート3：教訓の抽出（改善ループ・任意）

評価器または生成側のプロンプトを自動で磨く場合に使います。失敗事例（自己改善なら人間評価との乖離、他モデル基準なら判定の食い違い）を渡し、一般化できる教訓を抽出させます。

```
あなたは、評価の失敗事例を分析し、改善の教訓を抽出する分析者です。
以下の事例について、なぜ判定を誤ったのか、どう修正すべきかを、
今後の他のケースにも適用できる一般化された教訓の形で抽出してください。

【入力】
{SOURCE_INPUT}

【出力】
{OUTPUT}

【失敗・不一致の記録】
{FAILURES}
（各項目：質問ID、その質問への判定、期待される判定または基準モデルの判定、理由）

【抽出のルール】
- 個別事例そのものではなく、他のケースにも通用する原則として書く
- 「何を、どう判定すべきか」を具体的に述べる
- 1つの教訓につき1〜2文にまとめる

【出力形式】
{
  "lessons": ["教訓1", "教訓2"]
}
```

## テンプレート4：教訓の重複統合（改善ループ・任意）

抽出された教訓には重複が生じます。意味の重なるものを統合し、10件程度に絞ります。

```
あなたは、教訓リストの重複を整理する編集者です。
新しい教訓が、既存の教訓のいずれかと意味的に同じか判断してください。
同じであれば統合した1文を、異なれば新規として扱ってください。

【新しい教訓】
{NEW_LESSON}

【既存の教訓リスト】
{EXISTING_LESSONS}

【出力形式】
{
  "is_duplicate": true または false,
  "merge_index": 統合対象の既存教訓の番号（重複時のみ、0始まり）,
  "merged_lesson": "統合後の1文（重複時のみ）"
}
```

## テンプレート5：プロンプトの書き換え（改善ループ・任意）

確定した各教訓について、現行プロンプト内の該当箇所を特定し、教訓を反映した文面に置き換えます。教訓ごとに1回実行し、返ってきた置換を順に適用します。

```
あなたは、教訓に基づいて評価プロンプトを改訂する編集者です。
以下の現行プロンプトの中から、この教訓を反映すべき箇所を1つ特定し、
教訓を織り込んだ改訂版に書き換えてください。

【現行プロンプト】
{CURRENT_PROMPT}

【反映すべき教訓】
{LESSON}

【書き換えのルール】
- 現行プロンプトから、置き換える対象の一節をそのまま抜き出す
- その一節を、教訓を反映した改訂版に書き換える
- プロンプト全体ではなく、変更する一節だけを対象にする

【出力形式】
{
  "target_substring": "現行プロンプトから抜き出した、置き換える一節",
  "revised_substring": "教訓を反映した改訂版の一節"
}
```

改善ループの回し方：テンプレート2で評価→失敗を集める→テンプレート3で教訓抽出→テンプレート4で重複統合（10件程度に）→テンプレート5で各教訓をプロンプトに反映、を1周とします。自己改善の場合は、更新後プロンプトからテンプレート1で質問を再生成すると効果が出やすい傾向があります。

## 使うときの勘所

論文の検証から、以下が実務上の目安になります。

質問セットができたら、まず点検します。同じ軸の質問でYes率がばらついているか（全部Yesに寄っていないか）、質問どうしの相関が高すぎないかを見ると、分解がうまく機能しそうな軸と、質問を作り直すべき軸をあらかじめ見分けられます。

強みが出るのは、事実整合性のように誤りを特定の記述に紐づけられる基準です。逆に、全体の要旨を掴めているかといった全体的な印象で決まる基準は、細かい質問に割ると人間より厳しくなりがちで、かえって外れることがあります。過剰に細かい質問（登場人物や動機を一つ残らず問う類い）は避けます。

改善ループ（テンプレート3〜5）が効くのは、失敗の原因が「指示不足」のときだけです。書式の指定のように、明確に指示すれば守れる失敗は改善します。単語数を正確に数える類いの、能力そのものが足りない失敗は、指示を足しても直らず、プロンプトが肥大化して以前は守れていた項目まで崩れます。ループを回す前に、その失敗が指示で直る種類かを見極めるのが分かれ目です。

改善の大半は最初の1〜2周で得られます。回しすぎると教訓どうしが競合して劣化するため、早めに止めます。

採点役のLLMには、質問に的確に答えられるだけの読解力が必要です。分解は有効な設計ですが、非力なモデルの読解力を補うものではありません。影響の大きい用途では、人間の確認と組み合わせて運用します。
