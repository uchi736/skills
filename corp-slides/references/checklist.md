# 納品前チェックリスト

**姿勢: 問題はあると仮定して探す(欠陥ハント)。** 初回の出力はほぼ必ずどこか間違っている。
欠陥ゼロで通ったら見方が甘いと疑う。直したら該当ページを再レンダリングして見る。
ユーザーへの確認依頼は挟まず、直し切ってから納品する。

## 0. 機械で見る(毎回)

```
python build_deck.py                       # save() の「注意」が 0 件か。出たページは必ず目視
python <scripts>/export_preview.py deck.pptx
python <scripts>/check_deck.py deck.pptx   # issues: 0 になるまで直す
```

save() の「注意」が見るもの: はみ出し・泣き別れの見込み / lead が 2 文・主題名 / 結論帯の連続と 1/3 超 /
本文 3 枚未満の章 / 図解・グラフの無い章 / 表が本文の半分超 / 目次と中扉の章名の不一致 / 表紙の日付・部署の欠け / 関門表の不合格時の扱い・判定者が道具 /
目標線ラベルの向き / 打ち手の文末 / ガントの年度・ラベル幅 / 2 軸の重なり・強調なし など。

check_deck.py が見るもの: 再オープン可否 / プレースホルダらしき文字([ ]・XXXX・202X・TODO・○○。表の中も) /
空のプレースホルダ(PNG に写らない)/ 純黒・タイトルの継承色 / 12pt 未満の文字(出典・注・単位・ページ番号は除く)/
「〜について」で終わる文。

## 1. 視覚 QA(PNG を 1 枚ずつ Read で見る)

- [ ] 要素の重なり(文字にかかる線・矢印、注記と目標線、アイコンのラベル同士)
- [ ] 見切れ・はみ出し(箱・パネル・破線枠・スライド端)
- [ ] 語の途中の折り返し・1 文字だけの行(「〜す / る」)。文を削るか言い換えるか `\n` で切る
- [ ] 箱・パネルの下半分が空いていない(中身が薄い)。逆に詰まりすぎていない
- [ ] 並んだ箱の文字サイズ・項目数・文末の形が揃っている
- [ ] 出典・注記の行が本文に近すぎない
- [ ] 低コントラスト(淡背景に淡文字)がない
- [ ] タイトルが 1 行に収まっている

## 2. 全体

- [ ] 表紙 → 要旨 → 目次 → 中扉 → 本文 → 推奨・次の一手 → 結び の並び
- [ ] 表紙に会議名(回)・日付・作成部署がある。タイトルか副題に課題・目的がある
- [ ] 要旨が 目的 → 背景 → 実施内容 → 結果 → 結論 の順で、お願い帯がない
- [ ] 目次に各章のページ番号があり、最初の目次は章を強調していない
- [ ] 中扉に全章の一覧と現在地がある。中扉を挟む章は本文 3 枚以上(本文 10 枚未満なら中扉なしでよい)
- [ ] 各章に図解かグラフが 1 枚以上ある(表と箇条書きだけの章が無い)
- [ ] 進捗・中間レビューなら「ゴールに対する現在地」(goal_bars / timeline now= / gantt today=)がある
- [ ] 同じ型が 3 枚以上続いていない
- [ ] 結論帯(takeaway)がデッキの 1/3 以下で、2 枚連続していない
- [ ] 結びが完全な文で、次の一手(動詞・担当・期限)と連絡手段がある
- [ ] 16:9 で作っている(4:3 は依頼されたときだけ)
- [ ] ロゴ・コピーライト・ページ番号が出ている(表紙はページ番号なし)

## 3. 1 枚ごと

- [ ] lead が ▍1 文で、読み手に持ち帰らせる判断を言い切っている(説明・件数・型の説明・「〜について」・2 文になっていない)
- [ ] lead の主張を下の図表が証明している(数字・月・件数が lead・注記・結論帯と一致)
- [ ] lead が内容の全部を言っている(表+下段なら両方。グループを列挙するなら全部)
- [ ] 結論帯が lead の言い換えになっていない(担当・条件・次の判断など違う情報を足している)
- [ ] 箇条書きの階層が ■ → ● → □ に揃い、■ は名詞句・● は 1 項目 1 文・□ は 1 枚 1 か所
- [ ] 箱には役割+具体例・数字が入っている
- [ ] 題材に無い数字は (例)、案は (案) と明記し、source= に出所がある。年度・時点がある
- [ ] 実在の製品・OSS の評価やライセンスを断定していない(必要なら匿名化)
- [ ] 色がパレット内で、赤は負値・未達だけ。アイコンは BLUE 1 色
- [ ] 見出し帯の色が全て同じ BLUE(箱・柱・パネルで濃紺と青が混ざっていない)
- [ ] 表の様式が 2 系統の規則どおりか(数値・論証=濃色ヘッダ、図解・計画の格子=罫線だけ)。角丸の図形が無いか

## 4. 型ごとの見どころ

| 型 | 見ること |
|---|---|
| cover | 会議名・日付・部署があるか。タイトルが 1 行か |
| exec_summary | 4 項目の高さの配分が自然か。見出しが「■ 目的」で本文がその下か。結論が淡青の帯に中央揃えで 2 行以内か |
| content | ■ が 4 個以内・● が 6 個以内か。□ が 1 か所か。blocks は 2 列の読み順(左上→右上)で崩れていないか。各グループが同じ属性の並びなら表にしたか |
| boxes(柱) | 柱ごとに中身の種類が違うか(同じ属性が並ぶなら表)。行数の差が大きくないか |
| 概念図 | 凡例の番号と図の番号が対応し、図のラベルの語が凡例にあるか。アイコンが BLUE 1 色か。戻りの流れが破線か。ラベルが破線枠・隣と重ならないか |
| flow / boxes | 矢印ラベルが箱にかからないか。箱の文字サイズと文末が揃っているか |
| reason_tree | 結論帯が淡青で、根拠の見出し帯は他の型と同じ BLUE か。箇条が語の途中で折れていないか。根拠に数字があるか |
| gate_table | 関門名が確かめる対象の名詞句か。判定者が人か会議体か。合格ラインに向きがあるか。不合格時の扱いがあるか。下段が関門の直後に起きることか(次頁の案内・別の手順になっていないか)。下段があるなら lead が両方を言っているか |
| step_flow | 説明が 2 行以内で語の途中で折れていないか。下段が section_block で段の番号があるか |
| cycle_flow | 見出しが 6 字以内で矢印にかからないか。右欄が輪の言い換えでなく別の情報(詰まりどころ・成果物)か。中央の語が伝わるか |
| layers | hl / plan の意味が注にあるか。要素が 2 行以内か。層の順(上=利用者側)が自然か |
| swimlane | 矢印が箱や文字を横切っていないか。判定点が hl か。1 枡 1 箱か |
| tree | lead で名指しした枝が highlight か。葉が各 4 以内で語の途中で折れていないか |
| goal_bars | 低いほど良い指標に "lower" が付き「上限」「上限内/超過」と出ているか。補足に時点があるか。差の符号と色(未達=△ 赤)が合っているか。指標 5 つ以上なら表にしたか |
| chart | 定義行に年度があるか。値ラベルがあるのに値軸が残っていないか。lead の根拠の数字が図上にあるか。注記が棒・線・目標線にかからないか |
| chart(stack) | 合計が棒の上にあるか。系列名が最後の棒の右にあるか。計画が破線で区切られているか |
| chart_pair | 2 つの Q と lead の答えが対応しているか。目標線のラベルに向きがあるか |
| table | 数値の列の揃え。未達が △ 赤字+強調行か。セルの折り返しが 2 行以内で語の途中で折れていないか。論証なら担当の列があるか |
| matrix_eval | 凡例があるか。比較軸が ◎ の良い向きか。全軸◎の候補がないか。推奨列の △× を隠していないか |
| matrix_2x2 | 強調する項目だけが青か。両軸の端に対語(必要なら定義)があるか。象限名の語の形が揃っているか。ラベルの重なりがないか |
| timeline | 各フェーズの最後に出口条件があるか。期間に年度があるか。進捗なら now= の現在地があるか |
| gantt | 年度か起点があるか。色と破線の意味が注にあるか。濃紺は 1 本以下か。節目が判断名+時期か。バーのラベルが折り返していないか。進捗なら today= の青線があるか |
| process | 壁が「詰まる原因」か(判定結果・おそれになっていないか)。打ち手が動詞で終わり、頻度・期限・件数があるか。全工程に壁が付いていないか。lead に「輪」とあるなら loop=True か |
| message | 完全な文か(対句・キャッチコピーでないか)。次の一手に担当・期限があるか。連絡手段があるか |

## 5. 数値・言葉

- [ ] 単位・桁区切り・「予」「計画」の表記がある
- [ ] 棒グラフの軸が 0 始まり
- [ ] 表の空セルに `-`
- [ ] 体言止め基調で、です・ます と混在していない
- [ ] 社外向けなら社内略語・コードネームが残っていない

## 6. 別視点の検査(重要な資料)

作った本人は「期待した絵」を見てしまう。PNG を Explore サブエージェントに渡して検査させる。依頼文の例:

```
次のフォルダのスライド画像(スライド1.PNG〜スライドN.PNG)を全て Read で見て、欠陥を列挙してください。
問題は必ずあると仮定して探してください。観点:
- 要素の重なり・見切れ・語の途中の折り返し・1 文字だけの行・空きすぎ/詰まりすぎ
- 12pt 未満に見える本文、低コントラスト
- lead(青バーの 1 文)と図表の数字・内容の食い違い。lead が内容の一部しか言っていない
- 同じページ内で文字サイズや揃え・文末の形がばらついている箇所
出力: 「スライド番号 / 場所 / 欠陥 / 直し方」の表。欠陥が無いページは書かない。
フォルダ: <deck>_pptx_png
```
