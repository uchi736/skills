デッキ生成後、`export_preview.py` の実画像(PowerPointレンダリング)を**必ず目視**して確認する。

**姿勢: 問題はあると仮定して探す(欠陥ハント)。** 初回レンダリングはほぼ必ずどこか間違っている。
指摘ゼロで通ったなら、見方が甘い可能性を先に疑う。修正は別の問題を生みやすいので、
直したら該当スライドを必ず再レンダリングして見る。修正→再検証を1周以上回すまで完成と言わない。

## 視覚QA(欠陥ハント) — 実画像でこれを探す

- [ ] 要素の重なり(図形にかかる文字、文字を横切る線、積み重なった要素)
- [ ] 文字の見切れ(ボックス境界・スライド端で切れている、矢印ラベルの尻切れ)
- [ ] タイトルや見出しが2行に折り返して、下の罫線・要素と衝突していない
- [ ] 出典・脚注がすぐ上のコンテンツと衝突していない
- [ ] 間隔のムラ(片側だけ大きな空白、要素同士が触れそうに近い)
- [ ] 低コントラスト(淡背景に淡文字、濃背景に濃記号)
- [ ] テキストボックスが狭すぎて不自然な折返しが多発していない
- [ ] マトリクスのチップ・記号が枠線や他要素と重なっていない
- [ ] プレースホルダの残り(下の機械検査も併用)

**プレースホルダ機械検査**(目視の取りこぼし防止):
```python
from pptx import Presentation
import re
p = Presentation("out.pptx")
for i, s in enumerate(p.slides, 1):
    for sh in s.shapes:
        if sh.has_text_frame and re.search(r"\[|XXXX|202X|ipsum", sh.text_frame.text):
            print(i, repr(sh.text_frame.text[:60]))
```

**別視点の検査(重要資料)**: スライドPNGを Explore サブエージェントに渡し、
「問題はあると仮定して、重なり・見切れ・間隔・コントラストの欠陥を全て列挙せよ」と依頼する。
作った本人は「期待した絵」を見てしまうため、先入観のない目が効く。
