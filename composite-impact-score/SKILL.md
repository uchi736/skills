# 複合インパクトスコア構築スキル

研究成果に対して、単一指標では捉えきれない「総合的な影響度」を多次元シグナルから合成し、その妥当性を人間評価との一致で検証するためのスキル。

## このスキルを使うタイミング

- 論文や研究成果に「総合的な影響度」スコアを付与したい
- 研究のキュレーション・レコメンドのロジックを設計したい
- 単一指標（引用数だけ、星数だけ等）の偏りを補正したい
- 自動評価ロジックの妥当性を人手評価と照合したい
- LLM 評価器の補助シグナルとして客観的なスコアを用意したい

## 前提知識

**核心の主張**: 単一の影響度指標は分野・側面のバイアスが大きく、人間の「重要度」感覚と弱く相関する傾向がある。複数の異種シグナル（学術的注目・実装採用・社会的反響）を合成すると、個別指標を上回る人間整合性が得られる。

**なぜこれが効くか**:
- 各シグナルは異なる「インパクトの側面」を捉える
  - GitHub stars: 実装としての有用性（ソフトウェア波及）
  - Citation count: 学術的注目の総量
  - Influential citation count: 基礎的・本質的な影響
  - Altmetric: 社会・メディアへの波及
- 各シグナルは独立にヘビーテール分布を持つ → 対数正規化が必須
- 重み付けせず単純合計でも、4軸が補完しあって人間評価と一致しやすい（出典研究の経験則）

## ワークフロー

### Step 1: シグナルの選定

捕捉したい「インパクトの側面」を分解し、それぞれに対応する観測可能なシグナルを選ぶ。

| 捕捉したい側面 | シグナル例 |
|---|---|
| 実装・実用への波及 | GitHub stars, PyPI downloads, Hugging Face DL 数 |
| 学術的な注目総量 | Citation count |
| 本質的・基礎的な影響 | Influential citation count（Semantic Scholar 等） |
| 社会・メディア波及 | Altmetric score, X(旧Twitter) 言及数 |

**設計原則**:
- 3〜5 シグナルが目安。少なすぎると側面の偏り、多すぎると冗長化
- 異なるレイヤー（学術 / 実装 / 社会）を最低 1 つずつカバー
- 取得コスト・更新頻度・APIの安定性のバランスを取る

### Step 2: スケール係数と対数正規化

各シグナルは生値のままだとレンジが大きく違う（GitHub stars は数万、影響的引用は数件）ため、以下の変換を施す。

```
normalized_score = log_b (a * raw_score + 1)
```

- `a`（スケール係数）: 値が小さいシグナルを対数領域に十分乗せるための増幅
- `b`（対数の底）: シグナルのテール長さに応じて選択
- `+1`: ゼロ値での log の発散回避

**推奨パラメータ（出典研究の経験値）**:

| シグナル | a | b |
|---|---|---|
| GitHub Stars | 1 | e (≈2.718) |
| Citation Count | 1 | 8 |
| Influential Citation Count | 10 | 8 |
| Altmetric Score | 1 | 4 |

**パラメータ選択の指針**:
- 生値の代表的レンジが大きい → 大きい底 b
- 生値が小さく出やすいシグナル → スケール係数 a を大きく
- 正規化後の値が概ね 0〜数 のレンジに収まるよう調整
- 初回採用時は出典の推奨値で開始し、対象コーパスの分布を見て微調整

### Step 3: 合成

正規化スコアを単純合計する。

```
composite_score = sum(normalized_scores)
```

**重み付けを入れない理由**:
- 重み最適化は対象データ依存になり汎化しにくい
- 単純合計でも個別最強シグナルより人間評価との一致が高いという経験的知見
- 透明性が高くデバッグしやすい

**重み付きを試したい場合**:
- まず単純合計でベースラインを確立
- その後、人間評価との整合性最大化（ridge regression 等）で重みを同定
- 改善幅が小さいなら単純合計のまま運用

### Step 4: 人間評価との整合性検証

合成スコアの妥当性は人手評価との相関で確認する。**このステップを飛ばすと「もっともらしいけど人間感覚と乖離した」スコアを運用してしまうリスクがある**。

**サンプリング**:
- 対象コーパスから 200〜300 本程度をランダム抽出
- 分野が複数にまたがる場合は分野ごとに層別抽出
- スコア分布の上位・中位・下位がバランスよく入るようにする

**人間評価の設計**:
- 評価軸: 新規性（novelty）・堅牢性（soundness）・潜在的インパクト（potential impact）
- 上記 3 軸の平均を「人間評価値」とする
- 3 名以上の独立評価者を確保
- 評価者間でランダムに割り振り、対象論文ごとに平均をとる

**整合性指標**:
- Pearson 相関: 線形関係の強さ
- Spearman 順位相関: 順位の一致度
- 順位ベースの推薦タスクなら Spearman を主指標に

**判定基準（経験則）**:
- 合成スコア vs 人間評価で Spearman > 0.5 が一つの目安
- 個別シグナル単体の相関と比較し、合成が上回ることを確認
- 合成 < 個別最強 なら、シグナル選定または正規化を見直す

### Step 5: 分野別の感度分析

シグナルの相関は分野によって変動するため、サブグループ別の検証を行う。

**確認すべきこと**:
- 各シグナルの分野別相関
- 特定分野で著しく低相関なシグナルがないか
- 例: Altmetric は実装・応用系分野で強相関、純理論系分野で弱相関の傾向

**対処の選択肢**:
- 全分野で合成スコアが安定相関 → そのまま採用
- 特定分野で偏りが大きい場合:
  - 分野別に重みを変える（ただし複雑化のコスト）
  - 該当分野で弱いシグナルを除外したサブスコアを併用
  - 分野判定を先に行ってから別配合を適用

## 主な活用シーン

### 注目研究の自動選定
- 対象コーパスの論文全件にスコア付け
- 公開後 N 日時点でのスコア上位 → 人手チェック対象に
- 「sleeping beauty」型（後から伸びる）の見逃しを考慮し、定期再評価ジョブを回す

### レコメンドの強度づけ
- ユーザーの関心分野フィルタ × インパクトスコア で並べる
- 「あなたの関心領域で今週注目された研究」型の通知ロジック

### コンテンツ化・要約化の優先度
- スコアが高い × まだ取り上げていない → 新規取り上げ候補
- スコアが高い × 既に取り上げ済み → 追記・更新候補

### LLM 評価器の補助シグナル
- LLM に論文を評価させるタスクで、合成スコアを z-score 化して
  プロンプトに渡すと評価の安定性が増す

## チェックリスト

スコアを実運用に投入する前に:

- [ ] シグナルが「実装 / 学術 / 社会」など複数レイヤーをカバーしているか
- [ ] 各シグナルの生値分布を確認し、対数正規化後のレンジが揃っているか
- [ ] 200 本以上の人手評価サンプルで Spearman > 0.5 を確認したか
- [ ] 合成スコアが個別シグナル最強より高い相関を示しているか
- [ ] 主要なサブグループ（分野・公開時期）ごとに整合性を確認したか
- [ ] スコアの欠損ハンドリング（シグナルが取得できない場合）を定義したか
- [ ] スコア更新頻度と各 API の rate limit を整合させたか

---

## 制限事項と注意点

**遅延インパクトの見逃し**
引用や Altmetric は時間遅れで蓄積する。公開直後の論文は本質的な影響度に対してスコアが低く出る。後から評価が定着する "sleeping beauty" 型は見逃しやすい。
→ 公開後の経過時間で正規化するか、早期に動く実装系シグナル（GitHub stars の増加率）を併用。

**分野依存性**
社会的シグナル（Altmetric 等）は分野で相関が大きく変動する。特に純理論分野では信頼性が下がる。
→ 分野別の感度分析（Step 5）を必ず実施。

**循環性のリスク**
LLM で論文を評価し、その結果と合成スコアを相関させる構成にすると、LLM が既に学習しているインパクトの「事前知識」を再現するだけになりかねない。検証用の人手評価は LLM を介さない独立評価で実施する。

**閾値の絶対視を避ける**
Spearman > 0.5 は経験則。タスクの厳しさによって基準は変わる。順位上位 N 件の的中率（top-K accuracy）など、用途に即した指標と併用する。

**シグナル取得 API の不安定性**
Altmetric、Semantic Scholar、GitHub の各 API は仕様変更・rate limit・障害がある。本番運用ではキャッシュとリトライ、欠損時のフォールバックを設計しておく。

## 発展的応用

**動的スコアリング**
公開からの経過時間 t を変数に組み込み、`composite_score(t)` を時系列で追う。スコアの「伸び率」自体を新たなシグナルとして扱える。

**LLM 評価器への補助シグナル注入**
合成スコアを LLM の評価プロンプトに「補助シグナル」として渡すと、LLM 単独より人間評価との一致が改善する傾向がある（同系統の研究で +0.15〜0.29 の Spearman 改善が報告されている）。実装例：

```
このバッチの参考スコア（z-score 正規化済み）:
- index 0: 0.82
- index 1: -0.31
- index 2: 1.45
...
これは補助シグナル。各論文を独自の観点でも評価したうえで統合せよ。
```

**サブスコアの独立活用**
合成前の個別正規化スコアも保持しておくと、「学術的注目は低いが実装採用は高い」のような特異パターンの検出に使える。実装重視のユーザーに刺さる隠れた良研究の発掘などに有効。

**早期予測モデルとの組合せ**
スコア自体は遅行指標だが、これを ground truth として早期テキスト特徴から将来スコアを予測する別モデルを学習させると、公開直後の論文の予測ランキングが作れる（このアプローチは出典研究の本体テーマでもある）。

本スキルは、論文インパクト予測における複合シグナル設計と人間評価との整合性検証に関する研究領域に基づく。特に、研究成果の影響度を多次元で捕捉する手法と、ヘビーテール分布を持つ学術メトリクスの正規化手法に関する近年の研究知見を、実務適用しやすい形に再構成したもの。

具体的なパラメータ値（スケール係数 a・対数底 b）は 1 つの先行研究での経験値であり、対象コーパス・対象分野に応じた再キャリブレーションが推奨される。
